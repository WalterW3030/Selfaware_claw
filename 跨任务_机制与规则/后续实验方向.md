## 方向1：预载轮数剂量-响应曲线（Mode B）

**是哪方面的实验**：Mode B 的 few-shot 预载轮数（0/1/4/8轮）对规则遵守行为的剂量效应实验。

**目标**：测出 data_usage、dim3、dim1 随预载轮数变化的曲线形态，回答两个被等样本数据打开的问题：
1. "规则稀释"预测（轮数越少规则遵守越好）在 0/1/4 轮是否出现——等样本下 1 轮 C（du 60.4%）已低于 8 轮 B_M1M4（69.0%），需要确认这是轮数效应还是 B/C 消息结构差异；
2. "格式锁定收益"从几轮开始建立、是否有拐点或平台期（many-shot 平台期预测在 1 vs 8 两点间不成立，需中间点定位）。

**需要的工作**：
1. helpers 新增参数化预载：从 MODEB_PRELOAD（8轮，一字不动）截取前 N 轮，新增 `call_deepseek_step1_modeB_rounds(question, n)`；N∈{0,1,4}，8轮即现有 modeB；
2. CLI 增加 `--mode B_r0 / B_r1 / B_r4` 映射到该函数，映射写入 spec CLI 表；
3. spec 先更新：新增"Mode B 轮数梯度变体"章节，变量控制声明（仅预载轮数不同，system prompt 均为 V44_SYSTEM_PROMPT_MODEC，题库同 test_questions_100.json）；
4. 每档跑 100 题，三档共 3 次运行；输出命名 `test_100q_modeB_r{N}_YYYYMMDD_HHMMSS.json`；
5. 每档同配置重跑一次（用已测方差 du Δ4.0 点、逐题一致 72/100 作噪声底，差距须 >2 倍噪声才可下曲线结论）；
6. 分析输出：du/dim3/dim1 随轮数折线 + 逐题一致性矩阵（各档对 8 轮基准）。

**设计脚本所需参数**：函数名与签名、CLI 映射、预载截取规则（前N轮=MODEB_PRELOAD[:2N]）、题库路径、输出命名规则、指标口径（du/dim3 分母=dim1 pass 数，与现报告一致）、方差判定阈值（>8 点视为超噪声）。

## 方向2：33 题 data_usage 分歧内容归因

**是哪方面的实验**：分析性工作（非新跑数）——对 B_M1M4 与 C_M1M4 在 100 题中 du 判定分歧的 33 题（B 占优 19、C 占优 14）做内容级归因。

**目标**：判定分歧来源是（a）回答内容实质差异（结构、引用完整性不同）、（b）v4 评估器判定不稳定，还是（c）两者混合；产出结论决定是否需要评估器校准（关联挂起裁决：v4 评估器校准）。

**需要的工作**：
1. 写提取脚本：读三份结果 JSON（B_M1M4 152648、C 203223、C 212448），按题号对齐，筛出 du 分歧题，导出每题的 step2 提取文本、step4 回答、评估器判定理由，生成 33 题对照表；
2. 对 33 题逐题分类标注（引用缺失/引用错误/结构差异/评估器分歧），标注规则先写进 spec；
3. 对疑似评估器分歧的子集，用同一文本重复评估 3 次测评估器自身一致性；
4. 产出归因报告：各类占比 + 是否触发 v4 校准的判定。

**设计脚本所需参数**：三份结果文件路径、题号对齐键、du 字段路径（dim3_new/data_usage）、评估理由字段名、重复评估次数（3）、输出表结构（题号/双模式判定/理由摘要/分类）。

## 方向3：dim1 十题分歧归因

**是哪方面的实验**：能力边界识别（step1）分歧的归因实验——100 题中 dim1 判定不一致的 10 题（dim1 逐题一致 90/100）。

**目标**：区分这 10 题是（a）模式间真实的识别差异还是（b）step1 输出噪声。已知 C 两次同配置重跑 dim1 为 91 vs 94（自身有 3 题级波动），需判定分歧是否超出此噪声。

**需要的工作**：
1. 从结果 JSON 提取 10 题的 step1 原始回答（两模式），逐题对照"识别为 exceed/未识别"的判定与理由；
2. 对这 10 题做定向复现：用现有 modeB、modeC 函数各重跑 3 次（同题同配置），统计各题判定一致性；
3. 判定阈：某题在单模式 3 次重跑内判定一致 ≥3/3 且两模式判定相反 → 属真实模式差异；任一模式自身不一致 → 属噪声，不计入模式差异；
4. 产出 10 题逐题结论表。

**设计脚本所需参数**：10 题题号清单（从现有结果 diff 生成）、复用函数 `call_deepseek_step1_modeB/modeC`、每题重跑次数（3）、一致性判定阈（3/3）、输出表结构（题号/模式/3次判定/一致性/归因结论）。

## 方向4：缓存控制后的时间重测

**是哪方面的实验**：B_M1M4 与 C_M1M4 时间指标的受控复测——现有时间数据（step1 7.13 vs 7.73 等）受服务端缓存与负载波动污染，已定性"只报观测值不归因"，本方向回答受控条件下是否仍有差异。

**目标**：在排除 KV-cache 命中差异与时段负载差异后，重测两模式 step1/step4/total，判定等输入长度差（C 少 7 轮历史）是否产生可复现的时间差。

**需要的工作**：
1. 破缓存方案需 Walter 先裁决：方案 A 在预载尾部加随机盐（破坏缓存但改变预载内容，偏离 M1M4 一致性）；方案 B 不加盐，改用多次错峰重跑取分布（不破坏配置但无法完全排除缓存）；方案 C 若 API 侧提供缓存命中标识则直接记录标识分组统计；
2. 按裁决方案，两模式各跑 20 题 ×3 个时段；
3. 计时口径沿用 report 双口径（avg_step4_all / avg_step4_pass，分母标注）；结果仍只报观测值与分布，不作模式归因表述（遵守 step1 非归因规则）；
4. 产出时间分布对比表（分模式、分时段、含缓存标识如可得）。

**设计脚本所需参数**：破缓存方案（待裁决）、样本量（20题×3时段）、计时字段口径、输出表结构；复用现有计时与 report 生成代码。
