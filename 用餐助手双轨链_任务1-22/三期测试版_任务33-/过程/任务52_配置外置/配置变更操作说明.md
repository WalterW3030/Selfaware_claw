# 配置变更操作说明（任务52 · 配置外置）

> 本说明面向运维与后续任务执行人。
> 核心承诺：**今后更新模型或参考文件时，只改配置清单，不动任何脚本。**
> 唯一可配置源（母本）：`cloudfunctions/shared/assets.config.js`
> 部署形态：母本 + 三处部署副本（`cloudfunctions/aiGateway/`、`cloudfunctions/importRefTables/`、`common/`），四处同版本（见 §四）。

---

## 〇、变更总原则

1. 所有可配置项集中在 `cloudfunctions/shared/assets.config.js` 一个文件（母本）。
2. 三种高频变更（换模型 / 加换速查表 / 换 prompt 卡）都**只改母本清单**，脚本（aiGateway / importRefTables / recommend）一行不动。
3. 清单**缺件时函数拒绝执行并列出缺项**，绝不猜默认值继续跑。看到报错 → 按报错点名去补清单或补文件。
4. 清单**部署前置动作** = 把改后的母本复制到三处部署目录（aiGateway / importRefTables / common），**四处必须同版本**（见 §四）。

---

## 一、换模型（只改清单里对应 mode 的 model 字段一处）

**场景**：把某个功能位换用别的模型（例如把 `chat` 从 `deepseek/deepseek-flash` 换成别的）。

**操作步骤**：

1. 打开 `cloudfunctions/shared/assets.config.js`，找到 `MODEL_MAP`。
2. 只改对应 mode 那一行的 `model` 字段，一处即可：

```js
  chat: { channel: 'extend', model: 'deepseek/deepseek-flash' },
  //                      ↑ 只改这一个值
```

3. 保存 → 按 §四 把更新后的母本清单同步到三处部署目录 → 重新部署对应云函数。

**不要做的事**：不要改 `cloudfunctions/aiGateway/index.js` 等任何脚本；不要新增 mode（新增功能位属于开发任务，不在变更范围）。

---

## 二、加 / 换速查表（清单 EXPECTED_TABLES 加或改一行 + 传 md 文件）

**场景 A：新增一张速查表**（例如新表号 `102`）。

1. 把 md 文件传到云存储 `ref_tables/` 目录，文件名含表号数字段（如 `102新表标题.md`），或取精确文件名备第二步登记。
2. 清单 `EXPECTED_TABLES` 数组加一行：

```js
  { tableNo: '102', title: '新表标题', fileName: '102新表标题.md' },
```

   - 有精确文件名就登记 `fileName`（R 系列文件名不含表号的必须登记，如 051/062/058/068）。
   - 没有精确文件名就省略 `fileName`，导入器自动走数字段模糊兜底。
3. 如该表要进推荐默认装配，另行确认 recommend 侧"将查的表"清单（属开发变更，走任务书，不动脚本常量）。

**场景 B：换某张表的新版本文件**。

1. 新 md 传云存储 `ref_tables/`。
2. 清单里该 tableNo 那一行的 `fileName` 改成新文件名（走模糊兜底的表可不改清单，但建议登记精确名锁定）。

**不要做的事**：不要改 `cloudfunctions/importRefTables/index.js` 的匹配逻辑。

---

## 三、换 prompt 卡（清单改指向 + fileName，脚本不动）

**场景**：把某个角色换成新卡（例如详细卡 097 换新版本卡）。

1. 新卡 md 传云存储 `prompt_assets/`，文件名形如 `卡标题-AGT-xxxx.md`。
2. 清单 `EXPECTED_PROMPTS` 数组加新卡一行（promptId、title、fileName 逐字取自新卡 frontmatter）：

```js
  { promptId: 'AGT-xxxx', title: '新卡标题', fileName: '新卡标题-AGT-xxxx.md' },
```

3. 清单 `PROMPT_BINDINGS` 把对应角色的指向改到新 promptId：

```js
  CARD_DEEP: 'AGT-xxxx', // 详细卡（默认）
```

**只是换文件不换卡**（同卡 id 新文件）：只改 `EXPECTED_PROMPTS` 里该行的 `fileName` 即可，`PROMPT_BINDINGS` 不动。

**不要做的事**：不要改 `common/recommend.js`——卡 id 常量已从清单 `PROMPT_BINDINGS` 读取，脚本里没有卡 id 字面量。

---

## 四、部署注意（部署前置 = 复制副本，四处必须同版本）

0. **路径裁决（2026-10-10 复核，依据 devtools 单函数打包实测）**：微信开发者工具按**单个函数文件夹**打包上传，跨目录 `require('../shared/...')` 在云端不存在，必然 `Cannot find module`。故三个消费方脚本统一 `require('./assets.config.js')`（清单与脚本同目录），**部署前置动作（写死，不可省）**：

   ```bash
   # 在任务52交付目录下执行（或等价的文件复制操作）
   cp cloudfunctions/shared/assets.config.js cloudfunctions/aiGateway/assets.config.js
   cp cloudfunctions/shared/assets.config.js cloudfunctions/importRefTables/assets.config.js
   cp cloudfunctions/shared/assets.config.js common/assets.config.js
   ```

   - `common/recommend.js` 是前端件：`'../shared/'` 从 `miniprogram/common/` 解析到 `miniprogram/shared/`，而母本在 `cloudfunctions/shared/` 下，根本不在小程序代码包路径上——所以前端副本必须放在 `miniprogram/common/`（交付目录即 `common/`），同样 `require('./assets.config.js')`。

1. **三副本同版本检查清单（每次改清单后、部署前必做）**：

   ```bash
   diff cloudfunctions/shared/assets.config.js cloudfunctions/aiGateway/assets.config.js
   diff cloudfunctions/shared/assets.config.js cloudfunctions/importRefTables/assets.config.js
   diff cloudfunctions/shared/assets.config.js common/assets.config.js
   ```

   三条 diff 全部无输出 = 同版本，允许部署；**任何一条有输出 = 停止部署**，先复制同步再重来。禁止只更新一处（aiGateway 新表已导、importRefTables 还是旧清单这类半同步状态，会出现两函数行为不一致且报错信息对不上清单）。

2. 清单自检不通过（缺 MODEL_MAP 位 / 表项数不足 / 卡项数不足 / 角色绑定缺失或指向不存在的卡）时，函数**拒绝执行并在报错里列出全部缺项**。看到报错按点名补清单或补云存储文件，不要改脚本绕过。
3. 部署后冒烟：改清单后的首次调用若报 `Cannot find module './assets.config.js'`，即副本未复制进对应函数目录——回到第 0 步执行复制前置动作，不是改 require 路径。
4. 改动清单前建议先跑一遍负向单测确认环境健全：`node tests/assets_config_negative_tests.js`（在任务52交付目录下）。
