# 任务书：k2p6转交流水线_任务3（转交机制设计核验）

依据：任务清单（修订版）任务3；任务1（k2p6可程序化调用）、任务2（DeepSeek可调用+管线文件可导入）已过闸
执行规则执行版：A1-A4、C1-C4、D1-D3

## 目标
把"DeepSeek处理→超出能力边界转交k2p6→k2p6回复后DeepSeek继续完成"的转交环落成可执行设计，并逐环节核验可执行性。

## 实施步骤
1. 能力边界判定规则定稿：写出触发转交k2p6的全部条件清单（至少含：DeepSeek显式声明无法完成、调用出错、任务缺工具、达到预载对话轮数上限仍未完成），每条给出判定依据（如何从DeepSeek回复中识别该条件，如关键词、错误码、轮数计数）。
2. 转交通道逐环节核验（每个环节给出可执行路径与证据）：
   2.1 脚本调用DeepSeek（已证，引用任务2记录即可）
   2.2 脚本调用k2p6并另起会话：用任务1已证的openclaw infer model run路径，实测一笔"传入一段上下文文本+一个问题"的调用，贴响应原文
   2.3 k2p6回复传回脚本并解析（贴解析方式）
   2.4 脚本组织DeepSeek基于k2p6回复继续完成（说明调用结构：把k2p6回复作为什么角色消息传给DeepSeek）
3. 缺工具任务处理核验：写出"缺工具"的判定方式（如何识别任务所需工具不存在），确认实现路径为直接回复"无法完成"且不做任何模拟；给出一段示例回复文本。
4. 汇总落盘：转交机制设计文件一份，含判定规则清单、四环节证据、缺工具处理设计，附文件SHA-256。

## 完成判据
- 在能力范围内=判定规则成文且每条有识别依据+2.1至2.4四环节全部有可执行路径（2.2有实测响应原文）+缺工具处理设计成文
- 任一环节无可执行路径=按A2重试恰好一次，仍不通则停止并做A3停止登记

## 禁止项
禁止报密钥值；禁止无输出原文的结论；禁止把"理论上可行"当作核验通过（每个环节必须有实测或已证引用）；模板化"收到"不算确认——回复本任务书时复述判据两条、禁止项前三条、落盘要求后方可开工。
