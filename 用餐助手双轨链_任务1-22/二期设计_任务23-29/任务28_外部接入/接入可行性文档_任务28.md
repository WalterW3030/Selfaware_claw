## 2. 查证①：微信小程序读取微信运动步数

**结论：可以，官方原生能力。**

- **接口名称**：`wx.getWeRunData()`（微信官方 API，基础库 1.2.0+；返回用户**过去三十天**的微信运动步数，每日更新一次）
- **权限要求**：
  1. 用户授权 `scope.werun`（首次调用弹窗授权；拒绝后需 `wx.openSetting` 引导开启，需设计降级流程）
  2. `app.json` 声明 `"requiredPrivateInfos": ["getWeRunData"]`
  3. 小程序《用户隐私保护指引》中声明收集"微信运动步数"
- **标准获取流程**（两条路）：
  - **云开发方式（推荐，基础库2.7.0+）**：`wx.login` 拿 code（5分钟有效）→ `wx.getWeRunData()` 拿 cloudID → 云函数内 `wx.cloud.CloudID(cloudID)` 换取明文 `weRunData.data`（**必须检查 `weRunData.errCode`**，非0即授权失效）→ 存云数据库
  - **自建后端方式**：`wx.login` + `wx.getWeRunData` 返回 encryptedData+iv，后端用 session_key 解密。**注意**：官方安全基线禁止在前端/自建服务手动维护 session_key 解密（易泄露），推荐 CloudID 方式
- **限制**：仅真机调试可用（模拟器无步数数据）；步数 T 日数据 T+1 凌晨更新（适合做"昨日运动"而非实时）；iOS/安卓的微信运动来源分别是 Apple Health/系统计步（微信自己汇总的，不是全量）
- 来源：github.com/rixingyike/web-cloudbase-vue-template CLAUDE.md（2025-07-13，CloudID 规范流程）；wenku.csdn.net/doc/27o5wd0qzq（2025-11-23，uniapp 全流程含 app.json 声明）

## 3. 查证②：Apple Health/HealthKit 接入路径

**结论：小程序不能直读 HealthKit。标准路径 = 原生 iOS 伴随App做桥，或蓝牙设备直传小程序。**

- **HealthKit 本质**（2025-11-07，themomentum.ai 官方文档综述）：HealthKit 是 **iOS 原生本地框架**，数据存在用户 iPhone 本地；**没有云端 API、没有 REST**；所有访问必须经由用户 iPhone/Apple Watch 上的**原生 App**；逐数据类型逐项授权，用户可随时撤销；健康数据**不上 iCloud**
- **小程序（JS 运行时）无任何通道调用 HealthKit**——微信运行时不受信，Apple 不允许
- **可行路径 A（官方形态）：原生伴随App中转**
  1. 用户安装食知 iOS 伴随App（Swift，集成 HealthKit.framework）
  2. Info.plist 声明 `NSHealthShareUsageDescription` 等用途字符串，运行时申请读权限
  3. App 读取步数/体重/体脂/运动样本（含**其他App写入 Apple Health 的数据**，可用 `sourceRevision` 识别来源设备）
  4. 用户授权下上传食知后端 → 小程序从后端拉取
  5. 工程量：一个完整 iOS App 的开发/上架/审核，是五条路径里最重的
- **可行路径 B（轻量备选）：蓝牙体脂秤直连小程序**。微信支持 BLE API 套件（`wx.openBluetoothAdapter` / `wx.startBluetoothDevicesDiscovery` / `wx.createBLEConnection` / `wx.getBLEDeviceServices` / `wx.getBLEDeviceCharacteristics` 等），小程序可直接连接广播的体脂秤读取体重/体脂，**完全不经过 HealthKit**。市场上大量体脂秤小程序即此方案
  - 来源：juejin.cn/post/7407838946921463858（2024-08-28，小程序蓝牙 API 清单）
- **可行路径 C（无额外开发）**：iOS 用户微信运动数据本身来源于 Apple Health 汇总（查证①），`wx.getWeRunData` 拿到的步数对多数用户已覆盖核心需求
- 补充：第三方 App（Keep、小米运动健康等）同步进 Apple Health 的数据，原生 App 授权后同样可读（含来源标记）；HealthKit vs Health Connect 对比官方口径：**两者都无 server-side API、都必须有移动 App**（themomentum.ai 2025-11-07 对比表）

## 4. 查证③：安卓侧接入路径

### 4.1 Google Fit——正在退场，勿新接

- 官方迁移指南（developer.android.com，2026-09-10）：**"Google Fit API（含 REST API）仅支持至 2026 年底"**；2024-05-01 起已停止新开发者注册
- 历史数据不自动迁移，需 Google Takeout 导出
- **结论：新接入一律不做 Fit；存量用户需迁 Health Connect**

### 4.2 Health Connect——安卓官方标准，但只有原生 SDK

- Google 官方统一健康数据层，定位"Android 版 Apple Health"（本地加密存储、逐数据类型授权、新接入应用只能读**过去30天**数据、Android 14+ 预装）
- **接入方式**：仅 Android 原生 SDK（Jetpack `androidx.health.connect:connect-client`），**官方无 REST API**，路线图也无 REST 计划（volcengine.com 2026-06-24 整理官方文档确认）
- 三星健康、Fitbit、Polar 等伴侣 App 已写入 Health Connect——即一个原生 App 可读多品牌穿戴数据
- 云端集成走另一条线：**Google Health API**（原 Fitbit Web API 演进，按账号云端对接）
- **结论：小程序够不着（无 REST）；只有食知出 Android 原生 App 时才走这条，否则经用户授权共享链条绕**

### 4.3 华为 Health Kit——国内安卓最成熟，且有云侧 REST + 官方支持小程序场景

- 能力：云侧 **REST API**（增删改查运动健康数据）+ Android 端 SDK；步数/心率/睡眠/体重/血糖等类型分级开放
- 门槛：企业开发者实名认证 → 申请账号服务 → 申请 Health Kit 数据权限（**人工审核约15个工作日**，部分敏感类型有资质要求）→ 测试期 **100 用户限制**，验证通过后解除
- **小程序接入**：华为官方审核流程文档明确——"如您申请**微信小程序接入**，需邮件联系 hihealth@huawei.com 申请域名配置"（CSDN 华为官方博客 2023-09-14）
- 数据条件：华为穿戴设备绑定华为运动健康 App 并自动同步云侧后，REST API 才可读到
- 生态佐证：蚂蚁阿福 App 即通过"用户授权绑定华为运动健康账号"同步华为体脂秤体重体脂数据（sina.cn 2026-07-27）
- **结论：国内安卓（尤其华为机主）体重/步数/心率的正规通道；代价是企业资质+审核周期**

### 4.4 安卓侧小结

| 通道 | 形态 | 谁能接 | 现状 |
|---|---|---|---|
| Health Connect | 端上 SDK，无 REST | 原生App | 官方标准，活跃 |
| Google Fit API | 云+端 API | 任意 | **2026年底停用** |
| 华为 Health Kit | **REST API**+SDK | 企业开发者，**官方支持小程序后端调用** | 国内最成熟 |
| 小米运动健康 | 仅用户主动共享 | 指定平台（Keep/苹果健康/悦跑圈/Strava 等） | 无公开开发者API |

## 5. 查证④：Keep / 薄荷健康 / 小米运动 开放接口

### 5.1 Keep——无开放API，社区方案全部不合规

- 无官方开放平台/开发者文档。社区获取数据的实证路径只有：抓包网页版接口（`api.gotokeep.com`）+ 模拟登录 + 管理 token + 应对反爬（yihong0618/gitblog 2020-10 抓包实录；CSDN 2026-03-01《Keep运动数据爬虫避坑指南》仍走此路）
- 此类方式违反 Keep 用户协议，随时失效且有法律风险
- **结论：食知不做 Keep 数据自动接入**。Keep 在数据流里的位置是"汇聚方"（它接别人的穿戴数据），不是"供给方"
- 来源：github.com/yihong0618/gitblog issues/191（2020-10-22）；blog.csdn.net/vim8coder（2026-03-01）

### 5.2 薄荷健康——食物数据开放平台存在（重要勘正），但供给食物数据而非个人数据

- **薄荷健康食物数据开放平台**（原"薄荷健康食物数据开放平台"，现域名 ai.boohee.com / open.boohee.com）**真实运营中**，公开 API 列表：**食物搜索 / 食物详情 / 食物分类 / 食物列表 / 食物排行 / 食物图片识别 / 饮食记录 / 条码扫描 / 食物估重**（8000+估重图）
- 规模：**150万+食物条目、170+数据字段**；注册免费试用测试接口，完整功能付费开通；用户协议 2026-07-08 版
- 运营数据：日均 API 调用 3000万+；蚂蚁阿福拍餐识热量即调用薄荷饮食数据库（inews.qq.com 2026-07-08，蚂蚁战投薄荷新闻稿）
- **关键区分**：这是**食物营养数据供给**（食知"食物库"的上游候选），**不是**薄荷 App 用户的个人饮食/体重数据 API——薄荷用户的个人记录无对外通道
- 对食知意义：任务27"食物库只认权威数据源、禁众包"约束下，薄荷 API 是**商业授权数据源候选**（并列：中国食物成分表官方出版物/USDA FDC）；个人数据接入=无通道
- 来源：open.boohee.com 官网（2026年访问）；api.boohee.com 用户协议（2026-07-08）；view.inews.qq.com/a/20260708A08BI000（2026-07-08）

### 5.3 小米运动健康——仅"用户主动共享"，无开发者 API

- 官方隐私政策（2026-09-07）：支持用户在【我的】-【三方数据管理】将数据**主动共享至 Keep、苹果健康、悦跑圈等第三方平台**；可随时关闭
- 手表隐私政策（2026-02-28）：可向 Strava / Google Fit / Suunto / Health Connect 共享（步数/心率/卡路里/睡眠等）
- 澎湃 OS 开放数据接口权限列表（2023-03，现行页面）：运动健康类仅"心电图解读服务"一个 scope（12005），**无运动健康数据读取 scope**
- **结论：第三方无法经 API 拉取小米运动健康数据；但可利用其"共享链条"——用户把小米数据共享进 Apple Health / Health Connect 后，再走查证②/③的原生App路径**
- 来源：watch.iot.mi.com 隐私政策（2026-09-07）；watch.xiaomiwear.com 隐私政策（2026-02-28）；dev.mi.com 开放数据接口权限列表

## 6. 综合联动方案（食知小程序）

### 6.1 哪些数据能进、怎么进

| 数据项 | 进法 | 通道 | 频率 | 说明 |
|---|---|---|---|---|
| 步数 | 自动 | `wx.getWeRunData`（微信运动） | 每日（T+1） | 覆盖全体微信用户，零门槛 |
| 体重/体脂 | 自动 | 蓝牙体脂秤直连（微信BLE） | 每次测量 | 需选兼容秤型；不依赖任何生态 |
| 体重/体脂 | 手动 | 用户录入 | 每次 | 无设备用户兜底 |
| 体重/心率/睡眠（华为用户） | 自动 | 华为 Health Kit REST | 设备同步后 | 需企业资质+15工作日审核 |
| 步数/体重（iOS重度用户） | 自动 | iOS 伴随App + HealthKit | 每日 | 工程最重，按需立项 |
| 运动消耗 | 派生 | 步数→规则库换算（METs 查表） | 每日 | **规则引擎出数字，禁模型估算**（与任务27一致） |
| Keep/小米/薄荷个人数据 | — | 无合规通道 | — | 明确不做自动接入 |

### 6.2 优先级排序

- **P0（本期必做，纯小程序内可交付）**：
  1. `wx.getWeRunData` 步数接入——官方能力、无资质门槛、iOS/安卓通吃（iOS 来源即 Apple Health 汇总、安卓来源即系统/穿戴汇总）
  2. 体重/体脂**手动录入** + 蓝牙体脂秤直连——支撑任务27"身体测量"数据源
  3. 步数→运动消耗换算规则库——让数据进任务27的"运动消耗"数据类，闭环"摄入−消耗"日决策层
- **P1（商务/资质驱动）**：华为 Health Kit REST——国内安卓覆盖率高，申请企业资质+数据权限审核（预留约1个月），小程序经自家后端调用
- **P2（战略项，按需立项）**：iOS 原生伴随App + HealthKit——完整样本（运动/体征/实验室手动录入之外的部分）；Health Connect 同理仅在出安卓原生App时做
- **P3（并行评估）**：薄荷食物数据开放平台采购评估——属"食物库供给"线（任务27 §2.3），与"个人数据接入"线正交；与中国食物成分表官方数据做授权成本/覆盖度对比

### 6.3 与任务27数据体系的落地对接

- 每条外部样本带 `source` 字段（学 HealthKit）：`werun`（微信运动）/ `ble-scale:{model}`（蓝牙秤）/ `manual`（手录）/ `huawei-healthkit`（华为通道）——与任务27"每条 sample 带 source 来源标记"一致
- 单位与口径：微信运动步数=当日总步数（不是运动时长）；运动消耗换算走 METs 规则库（如 100 步≈X kcal 按体重分档查表），**禁止模型自由生成数字**
- 趋势判定沿用任务27双条件（幅度≥阈值且持续≥N天），外部数据与手录数据同等对待，冲突时设备自动源优先于手录、手录可覆盖
- 降级设计：用户拒绝 `scope.werun` 授权 → 提示"可手动录入运动消耗"并给 `wx.openSetting` 入口（不阻塞主流程）
- 隐私：步数属敏感个人信息，需在《用户隐私保护指引》明示收集范围、用途与存储期限（呼应微信小程序合规要求与任务27"医学诉求非医疗建议"声明）

## 8. 免责与不确定项
