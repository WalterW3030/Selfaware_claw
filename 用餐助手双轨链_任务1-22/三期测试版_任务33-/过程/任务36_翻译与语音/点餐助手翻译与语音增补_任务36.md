## 一、总览

两项新功能都**挂接在既有管线末端**，不改动识别/排序/搭配主干：

```
拍菜单 → 识图(recognize) → 确认门禁 → 排序/搭配 → 【最终候选锁定】
                                          │
                     ┌────────────────────┴────────────────────┐
                     ▼                                          ▼
              【菜单翻译 translate】                     【语音点单 order_phrase】
              （门禁通过后可选）                          （候选确认后→生成→用户确认→TTS）
                     │                                          │
                     ▼                                          ▼
              原文/译文对照展示                          WechatSI(普/英) + 腾讯云TTS(粤)
```

| 维度 | 菜单翻译 | 语音点单 |
|---|---|---|
| 触发时机 | 识别确认门禁**通过后可选** | **最终候选确认后**必经 |
| 功能位 | `translate`（hy3） | `order_phrase`（hy3） |
| 语种 | 普通话 / 粤语 / 英语 | 随话术语言，TTS 对应通道 |
| 输出 | 原文-译文对照 | 播报话术（文本先确认） |
| 失败降级 | 展示原文 + 提示重试 | 展示话术文本让用户自己念 |

## 二、菜单翻译

### 2.1 触发时机

- **门禁通过前不触发**：翻译的对象是"已确认菜名清单"，识别未确认时菜名不可信，翻译无意义。
- **确认门禁通过后**，在菜单结果区**可选**呈现入口：「🌐 翻译菜单」。
- 与双模式门禁衔接：快模式精简门禁同样在"低置信+价格缺失"处理完后放行翻译；门禁未通过时翻译按钮置灰。

### 2.2 三语选项

| 语种 | 代码 | 说明 |
|---|---|---|
| 普通话 | `zh_CN` | 目标语简中（外文菜单译入；中文菜单可译出英/粤） |
| 粤语 | `yue` | 目标语粤语书面语/口语 |
| 英语 | `en_US` | 目标语英文 |

> 交互：三选一（单选切换），默认跟随用户语言设置，无设置时默认 `zh_CN`。

### 2.3 翻译通道与模型

- **走 aiGateway 新增 `mode=translate`**，模型 **`hy3`**（与 copy/nutrition 同档，适合文本改写类任务，非 VL 无需识图）。
- 复用 `callAI('translate', messages)`，**前端禁止直连模型 API**（AGENTS.md 技术约束）。

**aiGateway `MODEL_MAP` 增量：**

```js
const MODEL_MAP = {
  recognize:    { channel: 'extend', model: 'deepseek-flash', thinking: 'off'    },
  copy:         { channel: 'extend', model: 'hy3'                             },
  nutrition:    { channel: 'extend', model: 'hy3'                             },
  order_fast:   { channel: 'extend', model: 'deepseek-flash', thinking: 'off'    },
  order_deep:   { channel: 'extend', model: 'deepseek-flash', thinking: 'medium' },
  chat:         { channel: 'extend', model: 'deepseek-flash', thinking: 'low'    },
  // ── 任务36 新增 ──
  translate:    { channel: 'extend', model: 'hy3'                             },  // 菜单翻译
  order_phrase: { channel: 'extend', model: 'hy3'                             }   // 点餐话术生成
}
```

### 2.4 结果与原文对照展示

- **对照布局**：左列原文（菜名/简介），右列译文，**逐行对齐**；保留 `name_confidence` 标记（低置信项译文加"待核"角标）。
- **硬约束字段一并翻译**：禁忌成分、过敏原标记必须随译，防止跨语言沟通丢失安全信息。
- **禁止增删菜名**：译文只能对应已确认清单，不得凭空添菜（与 order_phrase 同一条红线）。

**翻译 prompt 要点：**

```
role: 菜单翻译
硬约束:
  - 只翻译给定清单内的菜名与标记,不得新增/删除/合并任何条目
  - 过敏原/禁忌成分必须逐条对应译出,不得省略
  - 目标语: {{zh_CN|yue|en_US}}
字段裁剪:
  - 快速模式: 仅返回 {原名, 译文} 两列,不译长描述/营养
  - 深度模式: 返回 {原名, 译文, 成分标记译文, 备注}
```

### 2.5 双模式下的翻译粒度（对齐要求④）

| | 快速模式 | 深度模式 |
|---|---|---|
| 翻译范围 | **默认只译菜名清单**（`{原名, 译文}`） | 菜名 + 成分标记 + 简介备注 |
| 输出预算 | 收紧，单遍 | 全字段 |
| 时间预算 | 并入 ≤4s 预算内（翻译为轻量文本任务，hy3 快速档） | 并入深度 ≤15s |

> 快速模式"默认只译菜名清单"是**有意识的降级**：排队场景下用户只需认识菜名，长文本翻译挤占时间预算无收益。

## 三、语音点单

### 3.1 流程（四步，全必经）

```
① 最终候选确认  →  ② AI 生成点餐话术  →  ③ 用户确认话术  →  ④ TTS 播报
   (锁定清单)        (mode=order_phrase)      (文本可见可改)      (WechatSI/腾讯云)
```

### 3.2 第②步：话术生成（mode=order_phrase，hy3）

**aiGateway 调用：** `callAI('order_phrase', messages)`，模型 `hy3`。

**prompt 硬约束（对齐任务要求②）：**

```
role: 点餐话术生成
输入: 已确认候选清单(仅菜名 + 数量/备注) + 目标语言(zh_CN|yue|en_US)
硬约束:
  - 生成的菜名只许来自已确认候选清单,不得增删、不得改写菜名、不得杜撰菜品
  - 数量、口味备注以清单为准,不得臆造
  - 不输出价格、不输出营养数值(沿用网关红线思路)
输出:
  - 一段可直接对服务员说的口语化点餐要求
  - 目标语言与翻译选项一致
```

> **红线**：`order_phrase` 输出若出现清单外菜名，视为越权生成，前端拒绝采用并回退模板话术。可复用 `extractText` 后做"菜名白名单"校验（见 §六代码）。

### 3.3 第③步：用户确认话术

- 播报前**强制展示话术文本**，用户可**编辑再播**（如临时加"不要香菜"）。
- 未经用户确认**不自动播报**，避免误播。

### 3.4 第④步：TTS 播报（通道见 §四）

- 确认后按语种选择 TTS 通道播报。
- 播报中/播报后可重播；播报失败走降级（§五）。

## 四、播报通道

| 语种 | 主通道 | 说明 |
|---|---|---|
| 普通话 | **WechatSI 插件** | `lang=zh_CN`，`plugin.textToSpeech` |
| 英语 | **WechatSI 插件** | `lang=en_US` |
| 粤语 | **腾讯云 TTS（云函数转发）备选通道** | WechatSI 不支持粤语，走云函数 `ttsProxy` |

### 4.1 WechatSI（普通话 / 英语）

- 小程序插件 `WechatSI`（微信同声传译），`plugin.json` 声明后 `requirePlugin`。
- 调用：
```js
const plugin = requirePlugin('WechatSI')
plugin.textToSpeech({
  lang: lang === 'en_US' ? 'en_US' : 'zh_CN',
  tts: true,
  content: phrase,
  success: (res) => wx.createInnerAudioContext().src = res.filename,
  fail: () => fallbackToText(phrase)   // 见 §五降级
})
```

### 4.2 腾讯云 TTS（粤语备选通道）

- **云函数转发**：新建 `cloudfunctions/ttsProxy`，云端调腾讯云 TTS（TextToVoice / TTS 合成），返回音频 URL 或流。
- **密钥零硬编码**：`SecretId` / `SecretKey` 只读**环境变量**（对齐 aiGateway"密钥零硬编码"红线）。
- **测试版可置灰**：环境变量未配置时，粤语选项**置灰并标注"即将支持"**，不阻断普/英播报。

```js
// cloudfunctions/ttsProxy/index.js（要点）
const TTS_READY = !!(process.env.TENCENT_TTS_SECRET_ID && process.env.TENCENT_TTS_SECRET_KEY)
exports.main = async (event) => {
  if (!TTS_READY) {
    return { error: 'tts_not_configured', note: '粤语 TTS 通道未开通，测试版置灰' }
  }
  // 调腾讯云 TTS，语种 yue，密钥只读环境变量
  // ...返回 { audioUrl } 或音频流
}
```

> 前端逻辑：粤语按钮 `disabled = !TTS_READY`，点击时若置灰则提示"粤语播报即将支持"。

## 五、失败降级（对齐要求⑤）

| 失败点 | 降级行为 |
|---|---|
| **TTS 失败**（WechatSI fail / 腾讯云超时/未配置） | **展示话术文本，提示"请照此向服务员点单"**，用户可自己念；保留重播按钮 |
| 话术生成失败 | 回退**模板话术**（`"麻烦点：{{菜名列表}}"`），仍走确认→播报 |
| 话术含清单外菜名 | 拒绝该话术，回退模板话术 + 记录异常 |
| 翻译失败 | 展示原文，提示重试；不阻断点餐主流程 |
| 粤语 TTS 未开通 | 粤语按钮置灰"即将支持"，普/英不受影响 |

**降级红线**：任何降级都**不得丢失已确认候选清单**，不得静默失败（须有可见提示）。

## 七、与快速/深度双模式的关系（对齐要求④）

| | 快速模式 | 深度模式 |
|---|---|---|
| 菜单翻译 | ✅ 可翻译，**默认只译菜名清单** | ✅ 全字段（菜名+成分+简介） |
| 语音播报 | ✅ 可播报（话术精简、单句优先） | ✅ 可播报（话术可含搭配说明） |
| 话术篇幅 | 短（仅菜名+数量/备注） | 较长（可附推荐理由，但不含营养数值） |
| 时间预算 | 并入 ≤4s（translate/order_phrase 走 hy3 快速文本档） | 并入 ≤15s |
| 门禁衔接 | 精简门禁通过后开放翻译 | 完整门禁通过后开放翻译 |

> 两模式的**硬约束一致**：过敏原/素食过滤照旧在规则层，翻译与话术均**不得放行禁忌项**，也不得新增清单外菜名。

## 八、落地最小校验清单

1. **翻译仅在门禁通过后可用**；门禁未过时入口置灰（快/深两模式均验）。
2. `translate` / `order_phrase` 两功能位在 `MODEL_MAP` 生效，走 **hy3**，前端不直连 API。
3. **order_phrase 菜名白名单校验**：注入越权菜名时能拒绝并回退模板话术。
4. **TTS 通道**：普通话/英语走 WechatSI；粤语在 `ttsProxy` 环境变量配置后可播，未配置**置灰"即将支持"**。
5. **失败降级**：TTS 失败 → 展示话术文本供用户自念；翻译失败 → 展示原文，均不丢确认清单。
6. **快速模式翻译默认只译菜名清单**（对照深度全字段）。
7. **红线回归**：翻译/话术在任意模式、双模式切换、自由提问下均不越权新增菜名、不放行禁忌项。
8. 双模式**切换不丢已确认数据、不清购物车**（沿用任务32 §8，翻译/播报状态随之重算）。

## 【执行器补记】粤语通道选型理由（非模型产出）

> **来源标注**：本段为执行器（ds_kimi）按 Coordinator 指示（2026-09-23T17:36:37+08:00，三选一方案B）追加，**非流水线模型产出**；内容出处=《菜单翻译与语音点单选型调研_任务36输入.md》（commit b3dd73a）§二。原文档其余部分均为任务36流水线模型产出，未改动。

**为何粤语播报不走免费的微信同声传译插件**：WechatSI（微信同声传译）官方文档注明其 TTS **仅支持合成中文（普通话）语音**；其翻译能力虽标注支持粤语（yue），但**粤语播报音频不保证可用**。因此粤语播报单独走**腾讯云 TTS 基础音色**（明确支持粤语，3元/万字符）经 `ttsProxy` 云函数转发（密钥走环境变量），作为备选通道；测试版 UI 上粤语选项存在但置灰标注"即将支持"。普通话/英语播报仍走 WechatSI 主通道（免费零部署）。本文档 §五（播报通道）所列"WechatSI 普通话/英语 + 腾讯云粤语备选"结论不变，本段仅补齐选型推理。
