# 新会话初始化方案：继承记录/规则/行为模式 + 防工具塌缩复发

- mode=方案, version=v1, timestamp=20261115
- 任务来源：Walter命题（2026-11-15 14:36:48 经 Coordinator 派单）
- 背景事件：群 bot 两次工具大批量失效（`failed to call tool: unimplemented: 404 Not Found`，整批本地执行工具失效、消息工具正常、后整批从工具清单消失）；社区同型参考 openclaw/openclaw#199207
- 适用对象：Kimi 群"new"（Good2Eat）内 ds_kimi 侧 bot 的新会话（/new、/reset、会话重置、引擎重启后的首个会话）

## 一、命题

开新对话≠从零开始。目标是让新会话**自动继承**现有的记录、规则、行为模式，同时**不触发**工具塌缩类故障。难点在于：继承依赖"注入"，而注入内容变化本身就是已知的塌缩触发源之一（系统提示漂移→会话复用路径变化，参考 #199207 机制）。

## 二、继承机制官方依据（OpenClaw 文档原文摘录）

来源：`/usr/lib/node_modules/openclaw/docs/`（本机 Gateway 2026.x 随包文档）

1. **每次会话启动自动注入**（concepts/system-prompt.md, agent-workspace.md）：
   > "Bootstrap files are trimmed and appended under **Project Context**"——`AGENTS.md`、`SOUL.md`、`TOOLS.md`、`IDENTITY.md`、`USER.md`、`HEARTBEAT.md`、`MEMORY.md`（或 memory.md 小写回退）。
2. **注入上限**（concepts/context.md, agent-workspace.md）：
   > "Large files are truncated per-file using `agents.defaults.bootstrapMaxChars` (default `20000` chars)... total bootstrap injection cap across files with `agents.defaults.bootstrapTotalMaxChars` (default `150000` chars)."
3. **memory/ 日志不进常态注入**（reference/token-use.md）：
   > "`memory/*.md` daily files are not part of the normal bootstrap prompt; they remain on-demand via memory tools on ordinary turns, but bare `/new` and `/reset` can prepend a one-shot startup-context block with recent daily memory for that first turn. That startup prelude is controlled by `agents.defaults.startupContext`."
4. **MEMORY.md 须精简**（concepts/system-prompt.md）：
   > "Keep injected files concise — especially `MEMORY.md`, which can grow over time and lead to unexpectedly high context usage and more frequent compaction."
5. **会话状态位置**（concepts/session.md）：
   > "Store: `~/.openclaw/agents/<agentId>/sessions/sessions.json`; Transcripts: `~/.openclaw/agents/<agentId>/sessions/<sessionId>.jsonl`"——会话状态归 Gateway 所有，重置即新开 transcript。
6. **compaction 前自动记忆冲刷**（concepts/memory.md）：
   > "Before compaction summarizes your conversation, OpenClaw runs a silent turn that reminds the agent to save important context to memory files."

## 四、显式重注清单（新会话须主动恢复）

| # | 项 | 动作 | 依据 |

| 1 | 在途任务状态 | 读 memory/ 当日+昨日日志 + 存档仓过程目录，重建"已完成/在途/待验"三栏 | M4-4 中断恢复三步；会话 transcript 重置后不留存 |
| 2 | 当前有效指令 | 按时间戳排序群指令，旧指令作废跳过 | M4-2 指令因果排序 |
| 3 | 执行规则钩住 | AGENTS.md 已含开工纪律（skill汇报制/状态三栏/只报实测/更正不覆盖），新会话首轮开工消息即按此执行 | 规则文件本身自动继承，"钩住"靠首轮行为 |
| 4 | HALT/核对闸门状态 | 若有 HALT_STATUS.json 未释放，先读再动 | P11 核对闸门 |
| 5 | 输入绑定 | 批量执行前贴输入文件 SHA-256 + 前 3 行 | M3-1 |

## 五、防塌缩复发清单

| # | 做法 | 依据 |
|---|------|------|
| 1 | AGENTS.md 保持精简（现 15800/20000，留 20%+ 余量），只放规则原文，不放过程叙述 | 官方注入上限 + MEMORY.md 精简警告原文 |
| 2 | MEMORY.md 保持锚点式（指针+一行摘要），细节留 memory/ 日志 | 同上 |
| 3 | 会话中途不改规则/记忆类文件（AGENTS.md、SOUL.md、MEMORY.md），要改攒到会话边界（任务收尾或 /new 前） | #199207 根因=会话中途编辑 memory 文件→系统提示漂移→复用路径塌缩；Walter 要点提示第三条同款 |
| 4 | 心跳/cron 触发的工作区写入（memory 日志、monitor_state.json）属轻量增量，不整文件重写 | 降低漂移幅度的工程惯例 |
| 5 | 工具塌缩发作时的处置：立即停手→保留现场（报错串+时间窗）→报 Coordinator→等恢复或 /new；不反复重试工具调用 | #199207 观察：下轮自愈；反复调用只会污染现场 |
| 6 | 新会话首动顺序固定：读当日 memory → 读 AGENTS.md 已在注入 → 读存档仓在途状态 → 再开工 | M4-4 中断恢复三步 |
| 7 | 若 Gateway 侧可配置：`agents.defaults.bootstrapMaxChars`/`bootstrapTotalMaxChars` 维持默认即可（当前用量远低于上限，无需调整）；`startupContext` 保持默认（/new 首轮前置近日照，有利于会话恢复） | 官方默认值合理，不引入新变量 |

## 六、新会话初始化 SOP（可执行步骤）

新会话（或中断恢复）首个动作按序执行：

1. **读当日+昨日 memory 日志**（memory_get 或自然读取 memory/2026-MM-DD.md）——重建最近上下文。
2. **核对在途状态**：存档仓 过程/ 目录下当前任务文件夹 + 群内在途指令——确定"当前有效任务"。
3. **输出恢复状态报告**（M4-6 格式：执行日志/已完成/剩余/下一项）。
4. **开工**：收到 Coordinator 派单后，先 EEOP 加载回执 + 规格卡，再执行。
5. **会话进行中**：遵守防塌缩清单（中途不碰规则/记忆整文件；过程叙述落盘到 memory/ 不入 AGENTS.md）。
6. **会话收尾**：把关键决定/结果写入当日 memory 日志 + 存档仓过程目录，MEMORY.md 只更锚点。
