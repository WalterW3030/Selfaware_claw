## 一、总体定位（任务1）

### 产品定位
「食知」是一款面向用餐场景的轻量级知识助手小程序，核心宗旨是"让每一餐都有据可依"。不替代点餐平台，不连接餐厅系统，专注于在"吃"这个环节提供信息层支持。

### 目标用户（四层画像）

| 层级 | 画像 | 核心需求 |
|---|---|---|
| 第一层 | 健康关注者 | 控制热量、追踪营养、管理体重 |
| 第二层 | 美食探索者 | 了解菜品信息、发现新口味、分享体验 |
| 第三层 | 社交用餐者 | 拍照记录、生成文案、朋友圈分享 |
| 第四层 | 实用主义者 | 快速识别食物、获取基础信息、决策辅助 |

### 使用场景（五个典型场景）

1. **餐前决策**：站在菜单前，拍照识别菜品，了解热量和配料，决定点什么
2. **餐中好奇**：吃到不认识的食材，拍照识别，了解名称和营养
3. **餐后记录**：记录饮食，追踪每日营养摄入，管理健康目标
4. **社交分享**：生成有趣的菜品文案，配图片发朋友圈
5. **搭配咨询**：已有几道菜，问推荐搭配什么饮品或小菜

### 核心原则
- **轻量**：不追求大而全，聚焦用餐场景的信息需求
- **即时**：拍照即识别，输入即回答，不拖泥带水
- **可信**：数据来源标注清楚，不编造营养数据

## 二、输入处理方案（任务3）

### 三种输入形态

#### 1. 照片输入

**处理流程**：
```
用户拍照 → 本地预处理（压缩/裁剪/旋转校正）→ 视觉识别模型 → 结构化输出
```

**关键设计点**：
- **识别层**：多模态视觉模型（Qwen-VL、GPT-4o 等）做菜品识别
- **UX细节**：支持从相册选图或相机直拍；拍照后显示识别结果预览，用户可纠正
- **失败降级**：识别置信度低时，提示"未能识别，请尝试换个角度或手动输入"
- **隐私**：图片上传前压缩，原图保留在本地，不上传原图

#### 2. 文字输入

**处理流程**：
```
用户输入文字 → 意图识别 → 实体抽取 → 路由到对应功能模块
```

**关键设计点**：
- **意图识别**：轻量文本模型做分类（识别/文案/营养/搭配/其他）
- **多轮澄清**：意图模糊时，主动追问"您想了解这道菜的营养，还是想要一段分享文案？"
- **快捷输入**：支持语音转文字、常用语快捷输入

#### 3. 组合输入（照片+文字）

**处理流程**：
```
照片 + 文字 → 上下文融合 → 联合理解 → 输出
```

**典型场景**：
- **场景A**：照片是菜品，文字是"这个热量高吗"→ 识别菜品 + 查询营养
- **场景B**：照片是菜单，文字是"推荐两道素菜"→ OCR识别菜单 + 按约束推荐
- **场景C**：照片是食物，文字是"写个朋友圈文案"→ 识别食物 + 生成文案

### 统一输入层调度器

```
输入 → [类型检测] → 照片流 / 文字流 / 组合流
       → [意图路由] → 识别模块 / 文案模块 / 营养模块 / 搭配模块
       → [结果组装] → 统一输出格式
```

## 三、数据存储方案（任务5）

### 存储内容

#### 1. 用户身体数据

| 字段 | 类型 | 用途 |
|---|---|---|
| 身高 | 数值(cm) | 计算BMI、基础代谢 |
| 体重 | 数值(kg) | 计算BMI、热量需求 |
| 年龄 | 整数 | 营养需求计算 |
| 性别 | 枚举 | 营养需求计算 |
| 活动量 | 枚举(久坐/轻度/中度/重度) | 每日热量目标 |
| 饮食目标 | 枚举(减脂/增肌/维持/控糖) | 营养比例调整 |
| 过敏原 | 文本数组 | 识别和推荐时过滤 |

**存储方式**：本地优先（微信小程序 Storage），用户可导出/删除。

#### 2. 饮食记录

| 字段 | 类型 | 说明 |
|---|---|---|
| 记录ID | 字符串 | 唯一标识 |
| 时间戳 | 时间 | 用餐时间 |
| 餐次 | 枚举(早/午/晚/加餐) | |
| 菜品列表 | 数组 | 每道菜：名称、重量估算、热量、主要营养 |
| 照片 | URL/本地路径 | 可选 |
| 摄入摘要 | 结构化 | 总热量、蛋白质、碳水、脂肪、纤维 |

**存储方式**：
- 短期：本地缓存（最近7天）
- 长期：用户授权后同步到云端（用户自己的云盘/小程序后端）
- 原则：用户拥有数据所有权，可随时导出或删除

### 数据流设计

```
用户输入 → 识别/分析 → 结构化数据 → 本地存储
                              ↓
                        用户授权后同步云端
                              ↓
                        长期趋势分析（周/月报表）
```

## 四、功能设计（任务7/9/11/13/15）

### 功能1：食物识别（任务7）

**功能描述**
用户拍照或上传图片，系统识别菜品名称、主要成分、大致分量。

**可行性**
- **可行**：视觉识别技术成熟，多模态模型（Qwen-VL、GPT-4o）对常见菜品识别率较高
- **边界**：复杂菜品（混合食材、地方特色菜）识别准确率下降；需要用户确认和纠正机制

**模型选择**
- 主识别：多模态视觉模型（Qwen-VL、DeepSeek-VL、GPT-4o）
- 辅助：OCR模型（识别菜单文字）

**实现方案**
1. 前端拍照/选图，本地压缩后上传
2. 视觉模型识别，返回菜品名称 + 置信度
3. 置信度高（>0.8）：直接展示结果
4. 置信度中（0.5-0.8）：展示结果 + "对吗？不对请纠正"
5. 置信度低（<0.5）：提示"未能识别，请手动输入或换个角度"
6. 识别结果关联营养数据库，为后续营养分析做准备

**风险点**
- 幻觉识别：把A菜认成B菜 → 加用户确认环节
- 分量估算：照片角度影响分量判断 → 提示用户确认或手动调整

### 功能2：消息文案生成（任务9）

**功能描述**
基于菜品信息，生成适合社交平台分享的文案（朋友圈、小红书、微博等）。

**可行性**
- **可行**：文本生成是大模型的强项，只要输入结构化菜品信息，输出文案质量可控
- **边界**：需要用户提供风格偏好（文艺/搞笑/专业），否则可能不符合用户口味

**模型选择**
- 文案生成：文本LLM（DeepSeek-V3、Kimi、GPT-4o）
- 风格控制：通过prompt工程约束语气、长度、emoji使用

**实现方案**
1. 输入：菜品名称 + 识别结果 + 用户选择的风格标签
2. Prompt设计：
   - 角色：美食博主/营养师/搞笑达人（按风格切换）
   - 约束：字数（50字/100字/200字）、平台（朋友圈限制、小红书风格）
   - 输出：文案 + 可选话题标签
3. 用户可一键复制，或要求"再生成一版"

**风格选项**
- 文艺风："今晚的牛排，五分熟刚好，血橙酱汁是点睛之笔"
- 搞笑风："这碗面，吃完感觉能跑五公里——开玩笑的，我只想躺着"
- 专业风："今日午餐：三文鱼150g，优质蛋白+Omega-3，搭配藜麦饭"

### 功能3：营养分析（任务11）

**功能描述**
对识别的菜品进行营养成分分析，包括热量、蛋白质、碳水、脂肪、维生素等，并结合用户身体数据给出摄入建议。

**可行性**
- **可行**：营养分析基于结构化数据库查询 + 简单计算，不依赖实时外部数据
- **边界**：菜品分量估算有误差；营养数据来自数据库，覆盖面有限

**模型选择**
- 营养计算：规则引擎为主（查表+公式计算）
- 建议生成：轻量LLM（将计算结果翻译成用户友好的建议）

**实现方案**
1. **数据库层**：建立常见菜品营养数据库（每100g的热量、三大营养素、主要维生素）
2. **计算层**：
   - 输入：菜品名称 + 估算分量
   - 查询数据库获取每100g营养值
   - 按分量比例计算实际摄入
3. **对比层**：
   - 结合用户身体数据（BMR、每日热量目标）
   - 计算当前菜品占每日目标的百分比
4. **建议层**：
   - 轻量模型将数字翻译成建议："这道菜热量适中，蛋白质丰富，适合健身日"

**数据表示例（每100g）**
| 菜品 | 热量(kcal) | 蛋白质(g) | 碳水(g) | 脂肪(g) |
|---|---|---|---|---|
| 白米饭 | 130 | 2.7 | 28 | 0.3 |
| 红烧肉 | 470 | 12 | 8 | 42 |
| 清炒时蔬 | 45 | 2 | 6 | 1.5 |

### 功能4：搭配推荐（任务13）

**功能描述**
根据用户已有的菜品，推荐搭配的食物或饮品，实现口味互补、营养均衡。

**可行性**
- **可行**：搭配推荐是约束推理问题，可以用规则引擎或轻量模型实现
- **边界**：需要结构化输入（已有菜品列表），无法实时抓取餐厅菜单

**模型选择**
- 推荐逻辑：规则引擎优先（成本低、可解释性强）
- 复杂场景：轻量嵌入模型做语义匹配

**实现方案**
1. **输入层**：用户输入已有菜品（识别结果或手动输入）
2. **约束引擎**：
   - 硬约束：过敏原排除、素食过滤
   - 软约束：口味互补（重辣→清甜）、营养均衡（已有主食→推荐蛋白质）、浓淡平衡
3. **推荐生成**：
   - 基于搭配知识库（常见搭配规则）
   - 或轻量模型生成推荐
4. **输出**：推荐菜品/饮品 + 推荐理由

**搭配规则示例**
- 川菜/重辣 → 酸梅汤、绿豆汤（解辣）
- 油腻/红烧 → 清炒时蔬、凉拌黄瓜（解腻）
- 纯主食 → 蛋白质补充（蛋、豆制品）

### 功能5：智能点餐辅助（任务15）

**功能描述**
根据用户饮食偏好（素食/低碳水/过敏原）、预算和餐厅菜单，自动推荐最优菜品组合。

**可行性**
- **核心推荐逻辑可行**：约束优化问题，规则引擎或轻量模型可实现
- **外部依赖不可行**：实时抓取餐厅菜单、对接点餐系统下单

**模型选择**
- 推荐逻辑：规则引擎（成本最低、可解释性强）
- 复杂场景：轻量嵌入模型做语义匹配
- 交互层：小模型（7B级）做意图识别

**实现方案**
1. **输入层**：结构化菜单（菜品名、价格、过敏原标签、营养标签）
2. **约束引擎**：
   - 硬约束：过敏原排除、素食过滤
   - 软约束：预算上限、营养平衡
3. **优化目标**：预算内最大化营养覆盖或口味多样性
4. **输出**：推荐组合 + 理由（如"选A因为补充蛋白质，选B因为清淡解腻"）

### 功能6：用餐后评价与口味画像（任务15）

**功能描述**
用户用餐后输入评价或拍照，系统积累个人口味偏好数据，长期优化推荐精准度。

**可行性**
- **评价分析可行**：情感分析、口味关键词提取可用文本模型
- **画像归纳可行**：周期性汇总历史评价，生成偏好标签
- **外部依赖不可行**：照片识别（需图像模型）、跨会话持久化（无外部存储）、持续学习闭环

**模型选择**
- 评价分析：轻量文本模型做情感分类和关键词提取
- 画像归纳：中等模型周期性汇总历史评价

**实现方案**
1. **评价采集**：文本输入为主，照片由外部OCR/图像识别服务处理后转文本
2. **单条分析**：
   - 提取口味维度（辣/甜/咸/清淡）
   - 满意度评分
   - 重复意愿
3. **画像聚合**：
   - 按时间窗口汇总
   - 生成用户偏好标签（如"偏好川菜、中辣、避免油腻"）
4. **推荐联动**：画像标签作为功能5的软约束输入，形成"评价→画像→推荐"闭环

```
                           ↓

                           ↓
┌─────────────────────────────────────────────────────────┐
│                      数据层                              │

```

## 六、各功能可行性总表

| 功能 | 核心可行性 | 外部依赖 | 推荐模型 | 关键风险 |
|---|---|---|---|---|
| 食物识别 | 高 | 无 | 多模态视觉模型 | 幻觉识别、分量估算误差 |
| 消息文案 | 高 | 无 | 文本LLM | 风格不符合用户口味 |
| 营养分析 | 高 | 营养数据库 | 规则引擎+轻量LLM | 分量估算误差、数据库覆盖不全 |
| 搭配推荐 | 高 | 无 | 规则引擎 | 规则库覆盖不全 |
| 智能点餐辅助 | 中（算法可行，数据依赖外部） | 菜单数据 | 规则引擎 | 菜单获取难 |
| 口味画像 | 中（分析可行，持久化依赖外部） | 外部存储 | 轻量文本模型 | 数据积累周期长 |
