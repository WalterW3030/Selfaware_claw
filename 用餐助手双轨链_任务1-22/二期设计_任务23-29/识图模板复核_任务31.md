## ① 三模板 prompt 骨架的调整点

**核心新增变量:V4.1 Flash 思考默认开启(low/high/max 三档)——这是任务25设计时完全没纳入的维度。**

1. **三模板骨架都需新增"思考档位"字段,且取值不同**
- 理由:V4.1 Flash(2026-09-10)思考默认 on,而任务25 §六的速度分析只算了"图像编码次数+意图澄清轮+固定前缀缓存",**漏掉了思考 token 这一新增延迟/成本项**。识图是感知任务、营养 C 是数值翻译,都不需要深推理链,默认开思考会①拖慢端到端延迟;②挤占输出预算。
- 推荐取值:模板 A(识图)=**off 或 low**(求快);模板 B(文案)=low/medium;模板 C(营养)=low。

2. **图前"提示文字"与思考档位的搭配(本题重点)**
- 机制:任务25把"提示文字放图前"设计成**先验**。而思考档位与位置敏感性呈反向关系——**档位越低,模型越依赖输入的结构先验(位置影响越大);档位越高,模型有内部推理空间去重新权衡,位置影响被稀释。**
- 推论:模板 A 若按①用 off/low 求快 → 图前提示的**先验作用反而更关键**,位置设计必须精确(因为已没有思考轮来纠偏);反之若开高思考,位置可适度放松。
- 反向风险:高思考 + 强先验(如"在四川吃的")→ 易诱发**确认偏差**(模型找证据坐实"是川菜"),与 §六.4 的越界幻觉同属"先验压过输入"。建议 L6 补一条"仅依据图片证据,先验不得替代视觉判断"。

3. **L6 输出约束需补"token 预算 × 思考"的交互**
- 理由:流水线 K2P6_MAX_TOKENS=8192,思考默认开时推理 token 占输出预算,可能挤压结构化输出(菜名/置信度/份量)。背景报告已点名"推理 token 占用输出预算现象需留意"。→ 或对识图显式设 `thinking effort=low`。

4. **§六.3"结构化=最确定收益"需要加前提**
- 理由:该结论基于无思考模型行为;V4.1 Flash 默认思考,**思考文本与 JSON 结构输出的分离行为需实测**(是否污染 schema)。这是原结论的新前提。
