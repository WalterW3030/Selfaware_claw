# Kimi 功能调研：是否支持实验所需能力# 一、Kimi 核心能力（已确认）## 1.1 Tool Calling（工具调用）✅ **支持**- Kimi K2 Tool Calling 准确率：95.2%- Kimi K3 在 2026 年 8 月 tool calling 基准测试中排名第一（39.2 分）- 支持自定义 function calling 和内置工具## 1.2 内置工具列表✅ **全部支持**| 工具 | 类型 | 说明 ||------|------|------|| `$web_search` | builtin_function | 联网搜索（Moonshot 执行） || `Code-Runner` | 官方工具 | Python 代码执行 || `Quick Js` | 官方工具 | JavaScript 代码执行 || `Fetch` | 官方工具 | URL 内容提取 || `Excel` | 官方工具 | Excel/CSV 分析 || `Memory` | 官方工具 | 记忆存储和检索 || `Date` | 官方工具 | 日期时间处理 || `Convert` | 官方工具 | 单位转换 || `Base 64` | 官方工具 | 编码解码 |## 1.3 子代理能力✅ **支持**- Kimi K2.6 支持 Agent Swarm：最多 300 个子代理并行，4000 步协作- Kimi K2.5 支持最多 100 个并行子代理，1500 步协调- 支持模型级编排（model-level orchestration），模型自己分解任务并管理子代理## 1.4 上下文窗口✅ **充足**- Kimi K2.5/K2.6/K2.7：256K tokens- Kimi K3：1M tokens- 足以处理长对话和多步任务## 1.5 代码执行✅ **支持**- Kimi Code CLI：开源编码代理，支持代码读写、shell 命令、文件搜索- Code-Runner 工具：安全执行 Python 代码- 支持 200-300 步连续工具调用不漂移## 二、Kimi 在 OpenClaw 中的使用限制## 2.1 关键限制：Python 脚本无法 spawn Kimi ❌**这是架构限制，不是 Kimi 的问题**：- `sessions_spawn` 是 OpenClaw 的运行时工具- 只在 **Agent 对话上下文** 中可用- 独立 Python 进程（如 `test_modeA_full.py`）**无法调用**- 只有 Agent 在对话中直接调用 `sessions_spawn` 才能工作**结论**：Kimi 本身功能完全足够，但调用方式必须是 Agent 对话，不能是后台 Python 脚本。## 2.2 OpenClaw 配置要求（必须正确）⚠️ **否则 sessions_spawn 会失败**：| 配置项 | 正确位置 | 错误位置 | 失败表现 ||--------|----------|----------|----------|| `allowAgents` | `agents.list[].subagents` | `agents.defaults` | forbidden, allowed: none || `operator.admin` scope | 后端请求 | Gateway 可能剥离 | INVALID_REQUEST || `openclaw.json` 权限 | `1000:1000` | `root:root` | 回退到 allowed: none |## 2.3 已知 Bug：子代理完成信号丢失（Issue #50747）⚠️ **OpenClaw 问题，非 Kimi 问题**：- 子代理完成后，父会话可能收不到完成信号- 导致父会话永远卡在 processing- 消息队列阻塞**Workaround**：- 不用 `sessions_yield` 等待- 用状态文件检查子代理进度- 设置 `runTimeoutSeconds` 超时## 三、对实验的影响## 3.1 Kimi 能否处理实验中的任务？✅ **可以**- A 类（实时数据）：Kimi 有 `$web_search`，可以查股价、天气等 ✅- A 类（代码执行）：Kimi 有 `Code-Runner`，可以执行代码 ✅- C 类（特定知识查询）：Kimi 有 `$web_search`，可以查论文等 ✅- B 类（验证）：Kimi 可以搜索验证 ✅## 3.2 为什么之前 Kimi 没执行？❌ **不是 Kimi 不行，是调用方式错了**：| 问题 | 原因 | 解决方案 ||------|------|----------|| Python 脚本无法 spawn Kimi | 架构限制 | Agent 对话中直接调用 || 配置错误（allowAgents 位置） | 配在 defaults 而非 list | 改到正确位置 || scope 被 Gateway 剥离 | 已知 bug | 升级 OpenClaw || 完成信号丢失 | 已知 bug | 用状态文件替代等待 || 401 Unauthorized | API key 错误 | 换正确的 key |## 3.3 正确的调用方式```Agent 对话流程：1. Walter: 测试 A1（查特斯拉股价）2. Agent:   a. 调用 DeepSeek API（Step 1）   b. DeepSeek 声明 exceed   c. Agent 直接调用 sessions_spawn spawn Kimi subagent   d. Kimi subagent 执行 $web_search 查股价   e. Kimi 返回结果   f. Agent 调用 DeepSeek API 整合结果（Step 4）   g. Agent 汇报完整结果```**关键区别**：第 c 步的 `sessions_spawn` 由 **Agent 在对话中直接调用**，不是由 Python 脚本调用。## 四、结论1. **Kimi 功能完全足够**：搜索、代码执行、子代理、大上下文窗口，全部支持2. **Kimi API 可以用**：只要 key 正确，tool calling 工作正常3. **问题出在调用方式**：不是 Kimi 的问题，是 OpenClaw 的 `sessions_spawn` 必须在 Agent 对话中调用4. **配置需要检查**：`allowAgents` 位置、`operator.admin` scope、文件权限5. **需要绕过已知 bug**：不用 `sessions_yield`，用状态文件检查进度
