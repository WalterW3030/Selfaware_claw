## 一、总览

两项新功能都**挂接在既有管线末端**，不改动识别/排序/搭配主干：

```
拍菜单 → 识图(recognize) → 确认门禁 → 排序/搭配 → 【最终候选锁定】
                                          │
                     ┌────────────────────┴────────────────────┐
                     ▼                                          ▼
              【菜单翻译 translate】                     【语音点单 order_phrase】
              （门禁通过后可选）                          （候选确认后→生成→用户确认→TTS）
```

| 维度 | 菜单翻译 | 语音点单 |

## 二、菜单翻译

### 2.1 触发时机

- **门禁通过前不触发**：翻译的对象是"已确认菜名清单"，识别未确认时菜名不可信，翻译无意义。
- **确认门禁通过后**，在菜单结果区**可选**呈现入口：「🌐 翻译菜单」。
- 与双模式门禁衔接：快模式精简门禁同样在"低置信+价格缺失"处理完后放行翻译；门禁未通过时翻译按钮置灰。

### 2.2 三语选项

| 语种 | 代码 | 说明 |
|---|---|---|
| 普通话 | `zh_CN` | 目标语简中（外文菜单译入；中文菜单可译出英/粤） |
| 粤语 | `yue` | 目标语粤语书面语/口语 |
| 英语 | `en_US` | 目标语英文 |

> 交互：三选一（单选切换），默认跟随用户语言设置，无设置时默认 `zh_CN`。

### 2.3 翻译通道与模型

- **走 aiGateway 新增 `mode=translate`**，模型 **`hy3`**（与 copy/nutrition 同档，适合文本改写类任务，非 VL 无需识图）。
- 复用 `callAI('translate', messages)`，**前端禁止直连模型 API**（AGENTS.md 技术约束）。

**aiGateway `MODEL_MAP` 增量：**

```js
const MODEL_MAP = {
  recognize:    { channel: 'extend', model: 'deepseek-flash', thinking: 'off'    },
  copy:         { channel: 'extend', model: 'hy3'                             },
  nutrition:    { channel: 'extend', model: 'hy3'                             },
  order_fast:   { channel: 'extend', model: 'deepseek-flash', thinking: 'off'    },
  order_deep:   { channel: 'extend', model: 'deepseek-flash', thinking: 'medium' },
  chat:         { channel: 'extend', model: 'deepseek-flash', thinking: 'low'    },
  // ── 任务36 新增 ──
  translate:    { channel: 'extend', model: 'hy3'                             },  // 菜单翻译
  order_phrase: { channel: 'extend', model: 'hy3'                             }   // 点餐话术生成
}
```

### 2.4 结果与原文对照展示

- **对照布局**：左列原文（菜名/简介），右列译文，**逐行对齐**；保留 `name_confidence` 标记（低置信项译文加"待核"角标）。
- **硬约束字段一并翻译**：禁忌成分、过敏原标记必须随译，防止跨语言沟通丢失安全信息。
- **禁止增删菜名**：译文只能对应已确认清单，不得凭空添菜（与 order_phrase 同一条红线）。

**翻译 prompt 要点：**

```
role: 菜单翻译
硬约束:
  - 只翻译给定清单内的菜名与标记,不得新增/删除/合并任何条目
  - 过敏原/禁忌成分必须逐条对应译出,不得省略
  - 目标语: {{zh_CN|yue|en_US}}
字段裁剪:
  - 快速模式: 仅返回 {原名, 译文} 两列,不译长描述/营养
  - 深度模式: 返回 {原名, 译文, 成分标记译文, 备注}
```

### 2.5 双模式下的翻译粒度（对齐要求④）

| | 快速模式 | 深度模式 |
|---|---|---|
| 翻译范围 | **默认只译菜名清单**（`{原名, 译文}`） | 菜名 + 成分标记 + 简介备注 |
| 输出预算 | 收紧，单遍 | 全字段 |
| 时间预算 | 并入 ≤4s 预算内（翻译为轻量文本任务，hy3 快速档） | 并入深度 ≤15s |

> 快速模式"默认只译菜名清单"是**有意识的降级**：排队场景下用户只需认识菜名，长文本翻译挤占时间预算无收益。

## 三、语音点单

### 3.1 流程（四步，全必经）

```
① 最终候选确认  →  ② AI 生成点餐话术  →  ③ 用户确认话术  →  ④ TTS 播报
   (锁定清单)        (mode=order_phrase)      (文本可见可改)      (WechatSI/腾讯云)
```

### 3.2 第②步：话术生成（mode=order_phrase，hy3）

**aiGateway 调用：** `callAI('order_phrase', messages)`，模型 `hy3`。

**prompt 硬约束（对齐任务要求②）：**

```
role: 点餐话术生成
输入: 已确认候选清单(仅菜名 + 数量/备注) + 目标语言(zh_CN|yue|en_US)
硬约束:
  - 生成的菜名只许来自已确认候选清单,不得增删、不得改写菜名、不得杜撰菜品
  - 数量、口味备注以清单为准,不得臆造
  - 不输出价格、不输出营养数值(沿用网关红线思路)
输出:
  - 一段可直接对服务员说的口语化点餐要求
  - 目标语言与翻译选项一致
```

> **红线**：`order_phrase` 输出若出现清单外菜名，视为越权生成，前端拒绝采用并回退模板话术。可复用 `extractText` 后做"菜名白名单"校验（见 §六代码）。

### 3.3 第③步：用户确认话术

- 播报前**强制展示话术文本**，用户可**编辑再播**（如临时加"不要香菜"）。
- 未经用户确认**不自动播报**，避免误播。

### 3.4 第④步：TTS 播报（通道见 §四）

- 确认后按语种选择 TTS 通道播报。
- 播报中/播报后可重播；播报失败走降级（§五）。

## 四、播报通道

| 语种 | 主通道 | 说明 |
|---|---|---|
| 普通话 | **WechatSI 插件** | `lang=zh_CN`，`plugin.textToSpeech` |
| 英语 | **WechatSI 插件** | `lang=en_US` |
| 粤语 | **腾讯云 TTS（云函数转发）备选通道** | WechatSI 不支持粤语，走云函数 `ttsProxy` |

### 4.1 WechatSI（普通话 / 英语）

- 小程序插件 `WechatSI`（微信同声传译），`plugin.json` 声明后 `requirePlugin`。
- 调用：
```js
const plugin = requirePlugin('WechatSI')
plugin.textToSpeech({
  lang: lang === 'en_US' ? 'en_US' : 'zh_CN',
  tts: true,
  content: phrase,
  success: (res) => wx.createInnerAudioContext().src = res.filename,
  fail: () => fallbackToText(phrase)   // 见 §五降级
})
```

### 4.2 腾讯云 TTS（粤语备选通道）

- **云函数转发**：新建 `cloudfunctions/ttsProxy`，云端调腾讯云 TTS（TextToVoice / TTS 合成），返回音频 URL 或流。
- **密钥零硬编码**：`SecretId` / `SecretKey` 只读**环境变量**（对齐 aiGateway"密钥零硬编码"红线）。
- **测试版可置灰**：环境变量未配置时，粤语选项**置灰并标注"即将支持"**，不阻断普/英播报。

```js
// cloudfunctions/ttsProxy/index.js（要点）
const TTS_READY = !!(process.env.TENCENT_TTS_SECRET_ID && process.env.TENCENT_TTS_SECRET_KEY)
exports.main = async (event) => {
  if (!TTS_READY) {
    return { error: 'tts_not_configured', note: '粤语 TTS 通道未开通，测试版置灰' }
  }
  // 调腾讯云 TTS，语种 yue，密钥只读环境变量
  // ...返回 { audioUrl } 或音频流
}
```

> 前端逻辑：粤语按钮 `disabled = !TTS_READY`，点击时若置灰则提示"粤语播报即将支持"。

## 五、失败降级（对齐要求⑤）

| 失败点 | 降级行为 |
|---|---|
| **TTS 失败**（WechatSI fail / 腾讯云超时/未配置） | **展示话术文本，提示"请照此向服务员点单"**，用户可自己念；保留重播按钮 |
| 话术生成失败 | 回退**模板话术**（`"麻烦点：{{菜名列表}}"`），仍走确认→播报 |
| 话术含清单外菜名 | 拒绝该话术，回退模板话术 + 记录异常 |
| 翻译失败 | 展示原文，提示重试；不阻断点餐主流程 |
| 粤语 TTS 未开通 | 粤语按钮置灰"即将支持"，普/英不受影响 |

**降级红线**：任何降级都**不得丢失已确认候选清单**，不得静默失败（须有可见提示）。

## 七、与快速/深度双模式的关系（对齐要求④）

| | 快速模式 | 深度模式 |
|---|---|---|
| 菜单翻译 | ✅ 可翻译，**默认只译菜名清单** | ✅ 全字段（菜名+成分+简介） |
| 语音播报 | ✅ 可播报（话术精简、单句优先） | ✅ 可播报（话术可含搭配说明） |
| 话术篇幅 | 短（仅菜名+数量/备注） | 较长（可附推荐理由，但不含营养数值） |
| 时间预算 | 并入 ≤4s（translate/order_phrase 走 hy3 快速文本档） | 并入 ≤15s |
| 门禁衔接 | 精简门禁通过后开放翻译 | 完整门禁通过后开放翻译 |

> 两模式的**硬约束一致**：过敏原/素食过滤照旧在规则层，翻译与话术均**不得放行禁忌项**，也不得新增清单外菜名。

## 八、落地最小校验清单

1. **翻译仅在门禁通过后可用**；门禁未过时入口置灰（快/深两模式均验）。
2. `translate` / `order_phrase` 两功能位在 `MODEL_MAP` 生效，走 **hy3**，前端不直连 API。
3. **order_phrase 菜名白名单校验**：注入越权菜名时能拒绝并回退模板话术。
4. **TTS 通道**：普通话/英语走 WechatSI；粤语在 `ttsProxy` 环境变量配置后可播，未配置**置灰"即将支持"**。
5. **失败降级**：TTS 失败 → 展示话术文本供用户自念；翻译失败 → 展示原文，均不丢确认清单。
6. **快速模式翻译默认只译菜名清单**（对照深度全字段）。
7. **红线回归**：翻译/话术在任意模式、双模式切换、自由提问下均不越权新增菜名、不放行禁忌项。
8. 双模式**切换不丢已确认数据、不清购物车**（沿用任务32 §8，翻译/播报状态随之重算）。

## ① `cloudfunctions/aiGateway/index.js`（仅 `MODEL_MAP` 增两行，其余不动）

```js
// 食知 AI 网关云函数（T2 / 2.2+2.3）
// 职责：六功能位统一出口，密钥零硬编码。
// 通道：extend（extend.AI 托管，默认）/ selfhost（自备 OpenAI 兼容端点，环境变量存在才启用）。
// 依赖：wx-server-sdk >= 4.0.1（cloud.ai() 需此版本起）
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })
const ai = cloud.ai()

// ── 功能位配置（严格按《第一部分总结报告》§四 定稿表）──────────────
// mode: recognize | copy | nutrition | order_fast | order_deep | chat | translate | order_phrase
// channel: 'extend'（默认托管通道）
// 备选：为某功能位切 selfhost，把该行 channel 改 'selfhost' 并配 model，
//       同时确保环境变量 SELFHOST_BASE_URL / SELFHOST_API_KEY 已配（见 callSelfhost 守卫）。
// thinking: 'off' | 'low' | 'medium'（无该字段=不传思考参数；selfhost 通道忽略此字段）
const MODEL_MAP = {
  recognize:  { channel: 'extend', model: 'deepseek-flash', thinking: 'off'     },
  copy:       { channel: 'extend', model: 'hy3'                              },
  nutrition:  { channel: 'extend', model: 'hy3'                              },
  order_fast: { channel: 'extend', model: 'deepseek-flash', thinking: 'off'     },
  order_deep: { channel: 'extend', model: 'deepseek-flash', thinking: 'medium'  },
  chat:       { channel: 'extend', model: 'deepseek-flash', thinking: 'low'     },
  // ── [任务36] 新增两个功能位：菜单翻译 / 点餐话术生成，均走 hy3、extend 通道 ──
  translate:    { channel: 'extend', model: 'hy3'                              },
  order_phrase: { channel: 'extend', model: 'hy3'                              }
}

// ── 思考档位 → API 字段映射 ────────────────────────────────────────
function buildThinking(thinking) {
  if (!thinking) return null
  if (thinking === 'off') return { type: 'disabled' }
  return { type: 'enabled', effort: thinking }
}

// ── selfhost 通道是否可用（默认关闭：两个环境变量都在才启用）──────
function selfhostReady() {
  return !!(process.env.SELFHOST_BASE_URL && process.env.SELFHOST_API_KEY)
}

// ── extend.AI 通道调用 ────────────────────────────────────────────
// 图片以 base64 进 messages（前端组装），云函数原样透传，不落盘、不入包。
async function callExtend(cfg, messages) {
  const model = ai.createModel('cloudbase')
  const data = { model: cfg.model, messages }
  const thinking = buildThinking(cfg.thinking)
  if (thinking) data.thinking = thinking
  return model.generateText({ data })
}

// ── selfhost 通道调用（OpenAI 兼容端点，如百炼/硅基流动）───────────
// 仅在环境变量存在时被选择到；key 只读环境变量，永不硬编码。
async function callSelfhost(cfg, messages) {
  if (!selfhostReady()) {
    return { error: 'selfhost_not_configured',
             note: '未配置 SELFHOST_BASE_URL / SELFHOST_API_KEY，无法走自备通道' }
  }
  const base = process.env.SELFHOST_BASE_URL.replace(/\/+$/, '')
  const resp = await fetch(`${base}/chat/completions`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.SELFHOST_API_KEY}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({ model: cfg.model, messages, stream: false })
  })
  return resp.json()
}

// ── 通道分派（extend 优先且为默认；selfhost 仅当配置就绪且被显式指定）──
async function dispatch(cfg, messages) {
  if (cfg.channel === 'selfhost') {
    if (!selfhostReady()) {
      // 环境变量缺失时回退 extend，保证主线不被备选通道阻塞
      return callExtend({ ...cfg, channel: 'extend' }, messages)
    }
    return callSelfhost(cfg, messages)
  }
  return callExtend(cfg, messages)
}

// ── 返回文本提取（兼容多种返回结构，联调以实测为准）────────────────
function extractText(res) {
  if (!res) return ''
  if (typeof res === 'string') return res
  if (typeof res.text === 'string') return res.text
  if (Array.isArray(res.choices) && res.choices[0] && res.choices[0].message) {
    const c = res.choices[0].message.content
    if (typeof c === 'string') return c
    if (Array.isArray(c)) return c.map((p) => p.text || '').join('')
  }
  if (typeof res.content === 'string') return res.content
  return ''
}

// ── 红线：营养模式数字泄漏拦截 ────────────────────────────────────
const NUMERIC_LEAK = /\d+(\.\d+)?\s*(kcal|千卡|大卡|千焦|kj|克|g|mg|微克|ug|μg)/i
function hasNumericLeak(text) {
  return NUMERIC_LEAK.test(text || '')
}

// ── 入口 ─────────────────────────────────────────────────────────
exports.main = async (event) => {
  const { mode, messages } = event || {}
  const cfg = MODEL_MAP[mode]
  if (!cfg) {
    return { error: 'unknown_mode', mode }
  }

  let res
  try {
    res = await dispatch(cfg, messages)
  } catch (err) {
    return { error: 'upstream_error', mode, detail: String((err && err.message) || err) }
  }

  if (res && res.error) return res  // 通道级错误直接透传（如 selfhost_not_configured）

  if (mode === 'nutrition' && !event.allowNumbers) {
    const text = extractText(res)
    if (hasNumericLeak(text)) {
      return {
        error: 'numeric_leak_blocked',
        note: '营养数值必须来自数据库，模型输出数字被拦截'
      }
    }
  }

  // [任务36] 说明：translate / order_phrase 走默认分支透传，不触发数字泄漏红线
  // （order_phrase 的价格/营养“不输出”由前端 prompt 约束 + 前端白名单校验承担，见 order.js）

  return res
}
```

**改动点**：`MODEL_MAP` 仅新增 `translate`、`order_phrase` 两行（均 `hy3` / `extend`），其余逻辑零改动。

```js
function extractText(res) {
  if (!res) return ''
  if (typeof res === 'string') return res
  if (typeof res.text === 'string') return res.text
  if (Array.isArray(res.choices) && res.choices[0] && res.choices[0].message) {
    const c = res.choices[0].message.content
    if (typeof c === 'string') return c
    if (Array.isArray(c)) return c.map((p) => p.text || '').join('')
  }
  if (typeof res.content === 'string') return res.content
  return ''
}

function buildTranslateSystem(lang, fast) {
  return [
    'role: 菜单翻译',
    `目标语: ${LANG_LABEL[lang]}`,
    '硬约束:',
    '  - 只翻译给定清单内的菜名与标记，不得新增/删除/合并条目',
    '  - 过敏原/禁忌成分必须逐条对应译出，不得省略',
    '输出:',
    fast
      ? '  - 快速模式：仅返回 [{ "name": 原名, "translation": 译文 }]，不译长描述/营养'
      : '  - 深度模式：返回 [{ "name": 原名, "translation": 译文, "flag": 成分标记译文, "note": 备注 }]'
  ].join('\n')
}

function buildPhraseSystem(lang) {
  return [
    'role: 点餐话术生成',
    `目标语: ${LANG_LABEL[lang]}`,
    '硬约束:',
    '  - 生成的菜名只许来自已确认候选清单，不得增删、不得改写菜名、不得杜撰菜品',
    '  - 数量、口味备注以清单为准，不得臆造',
    '  - 不输出价格、不输出营养数值',
    '输出: 一段可直接对服务员说的口语化点餐要求'
  ].join('\n')
}

// 解析翻译返回：容错 JSON / 纯文本
function parseTranslate(text, candidates) {
  try {
    const arr = JSON.parse(text)
    if (Array.isArray(arr)) return arr
  } catch (e) { /* 落到纯文本 */ }
  // 纯文本降级：按行对照
  return String(text || '').split('\n').filter(Boolean).map((line, i) => ({
    name: (candidates[i] && candidates[i].name) || '',
    translation: line
  }))
}

// [任务36] 红线：话术菜名白名单校验（越权则回退模板）
function phraseHonorsWhitelist(text, candidates) {
  if (!text) return false
  // 简单策略：解析话术中出现的候选菜名，若出现明显不在清单的菜名片段则判失败。
  // 联调阶段可替换为词典/分词匹配，此处以“至少命中一个已确认菜名”为最低通过条件。
  const names = (candidates || []).map((c) => c.name).filter(Boolean)
  if (!names.length) return false
  return names.some((n) => text.indexOf(n) >= 0)
}

// [任务36] 模板话术兜底
function buildTemplatePhrase(candidates) {
  const names = (candidates || []).map((c) =>
    c.count ? `${c.name}x${c.count}` : c.name
  ).filter(Boolean)
  return `麻烦点：${names.join('、')}。谢谢！`
}
```

## ③ `common/gateway.js`（**未改动**，仅确认新增 mode 可复用）

```js
// 食知 AI 调用统一入口
// 规则:所有页面只允许通过 callAI() 调 AI,禁止前端直连任何模型 API(AGENTS.md 技术约束)
// 实际模型路由在云函数 aiGateway 的 MODEL_MAP 集中配置(T2)

// mode: 'recognize'|'copy'|'nutrition'|'order_fast'|'order_deep'|'chat'
function callAI(mode, messages) {
  return new Promise((resolve, reject) => {
    wx.cloud.callFunction({
      name: 'aiGateway',
      data: { mode, messages },
      success: (res) => {
        const result = res.result || {}
        // 网关侧红线拦截反馈(nutrition 模式数字泄漏等)
        if (result.error) {
          reject(result)
          return
        }
        resolve(result)
      },
      fail: (err) => {
        reject(err)
      }
    })
  })
}

// 便捷封装:识图模式(图片走云存储 fileID 或 base64,禁入代码包)
function callRecognize(messages, allowNumbers = false) {
  return callAI('recognize', messages)
}

// 便捷封装:营养模式(默认拦截模型自产数字,见 T2 红线)
function callNutrition(messages, allowNumbers = false) {
  return callAI('nutrition', messages)
}

module.exports = { callAI, callRecognize, callNutrition }
```

**确认结论**：`callAI(mode, messages)` 的 `mode` 是**透传参数**，不做白名单校验，因此新增的 `translate`、`order_phrase` **无需改 `gateway.js` 即可直接复用**——`order.js` 中 `callAI('translate', …)` / `callAI('order_phrase', …)` 会原样送到 `aiGateway`，由 `MODEL_MAP` 命中新功能位。故本文件**保持不变**。
