# OpenClaw 消息堆积根治方案（非重启）# 一、为什么反复重启不能根治反复重启只能清理当前卡死的状态，但如果不改配置和用法，子代理完成信号丢失的 bug 会再次触发。根治需要改配置 + 改用法。## 二、立即配置修改（5分钟完成）### 2.1 修改队列模式（最关键）当前默认是 `steer` 模式——新消息注入到当前运行中，如果当前运行卡住，新消息永远等待。改为 `followup` 或 `collect`：```json5// ~/.openclaw/openclaw.json{  messages: {    queue: {      mode: followup,      // 或 collect      debounceMs: 500,      cap: 20,      drop: summarize    }  }}```**区别**：- `steer`（默认）：新消息注入当前运行，当前运行卡住 = 全部阻塞 ❌- `followup`：新消息排队等待下一次运行，不阻塞当前运行 ✅- `collect`：合并多个排队消息为一次运行 ✅**推荐**：日常对话用 `followup`，批量任务用 `collect`。### 2.2 设置子代理超时```json5{  subagents: {    defaults: {      runTimeoutSeconds: 300,  // 5分钟超时，防止无限等待      maxSpawnDepth: 2,        // 最多嵌套2层      announceQueue: {        mode: collect      }    }  }}```**效果**：子代理如果5分钟没完成，自动超时，父会话不再等待。### 2.3 限制上下文大小```json5{  agent: {    max_context_tokens: 24000,    // 留 headroom    compaction: {      memory_flush: {        enabled: true      }    }  },  memory: {    search: {      rememberAcrossConversations: false  // 不跨会话记忆，减少上下文    }  }}```**效果**：防止 MEMORY.md 膨胀导致每次请求携带大量上下文。### 2.4 内存保护```json5{  gateway: {    timeout: 120000,      // 120秒超时    retryAttempts: 3,     // 重试3次    retryDelay: 2000      // 2秒间隔  }}``````bash# 设置 Node.js 内存上限export NODE_OPTIONS=--max-old-space-size=2048```## 三、用法调整（避免触发 bug）### 3.1 不要用 `sessions_yield` + `streamTo: parent`这是已知 bug 触发组合（Issue #48250）。**替代方案**：```python# ❌ 不要这样：sessions_spawn(task, mode=session)sessions_yield(streamTo=parent)  #
