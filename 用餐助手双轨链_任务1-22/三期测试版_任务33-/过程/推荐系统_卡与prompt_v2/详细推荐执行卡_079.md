# 详细推荐执行卡

## 适用

完整需求提取与逐候选分析。动词：分析/推荐/评估。候选多、需求杂、需完整记录。

**默认卡**：进食者未显式说明"快速"时，一律用本卡。

## 管线

| 步骤 | 动作 | 关键约束 |
|---|---|---|
| 0 | 场景判定 | 加菜 / 重新点餐。默认独立。跨场景延续须声明 |
| 0.5 | 用户要求过滤 | 最高标准。不符者出局。冲突→声明询问。无剩余→如实说，不凑数。**程度词（"不太/别太/不要太"）须同时提取为排序因子** |
| 0.6 | 通用底线过滤 | **默认激活，无论用户有无特殊需求**。查 R9（062），五维度逐一检查；不通过→降级或出局；触发例外须声明理由 |
| 1 | 需求提取 | 目的→第一级。缺口→第二级。搭配类→味型+成分双维。健康限制→硬性过滤。**本次用餐全部要求须写入需求清单**。底线未过者不进入此步 |
| 1.5 | 稳定性判定 | 触发：模糊指令 或 候选>12。维度：成熟度/波动度/流行度。高者优先，同层级随机。依据 033 |
| 2 | 前置过滤 | 忌口/重选。信息不足→按含有处理，移出 |
| 3 | 候选转写 | 按成分构成与已知效应→味型层/成分层双陈述。**数值负荷（辣度/糖度/盐度等）须逐项标注，不得省略**。**识图时：先读图例/说明文字判定标注体系，再逐项对照菜品旁符号计数，不得跳步或凭记忆补全**。**辣度识别：菜单有图例或自有分级体系时以菜单为准；无图例时按符号数目在菜单内排序相对辣度，不对应微辣/中辣等绝对名称，不跨菜单比较。标注体系查 051**。禁名称标签 |
| 4 | 方向核对 | 逐维比对：命中/部分命中/未命中。**多菜品时逐个添加，每加一个菜更新整体负荷状况** |
| 4.5 | 支持度标注 | **每个推荐举例生成时同步标注：有来源 / 部分支持 / 无支持**。依据见"支持度标注规则" |
| 4.6 | 无支持项查证 | 标注"无支持"的项→查证其关键特性（口味强度/成分/禁忌/适用人群）是否符合各维度基本要求；查证通过→保留并附依据；未通过→移除并声明。**查证与初稿隔离作答** |
| 5 | 加权汇总 | 维度权重→三值结论。部分命中必附代价 |
| 6 | 输出 | 需求清单/匹配结果/参数记录/局限声明 |

## 支持度标注规则

| 标注 | 判定标准 | 处置 |
|---|---|---|
| 有来源 | 该项可直接由速查表（016/020/058/068/062）或菜单文本支撑 | 直接进入输出 |
| 部分支持 | 方向有表支撑，但具体特性（强度/禁忌）未在表中 | 保留，输出中标注"特性未查证" |
| 无支持 | 该项来自联想、常识或记忆，无任何表内依据 | 必须经步骤 4.6 查证，否则移除 |

**标注对象**：所有推荐举例（具体品种、具体品类特性声明）。类型级推荐（如"乳基饮"）若方向来自速查表，标"有来源"。

**已知局限（如实声明）**：标注依赖模型自评，自评不准时无支持项可能漏检（Lanham et al. 2023）。此为本机制的固有代价。

## 过滤优先级

1. 用户要求（含程度词） 2. 健康限制 3. 通用底线（R9） 4. 稳定性 5. 忌口重选 6. 方向核对

## 参数

| 参数 | 默认 | 调节 |
|---|---|---|
| 级间权重 | 目的占优 | 目的模糊→提高缺口 |
| 维度权重 | 均衡 | 健康→成分层；感官→味型层 |
| 匹配阈值 | 中位 | 候选少→下调；多→上调 |
| 限制严格度 | 不可协商 | 显式声明方可下调 |
| 稳定性阈值 | 12 候选 | 超出触发 1.5 |
| 随机允许度 | 同层级内 | 稳定性并列时启用 |
| 程度词敏感度 | 高 | "不太/别太"等→写入排序因子 |

## 微示例（步骤 3）

```
候选：X
味型层：方向 = [A]、[B]；负荷 = [数值1]
成分层：方向 = [C]、[D]；负荷 = [数值2]
（负荷记法：菜单内相对量，如辣度=符号数目N；不转写为绝对分级名称）
```

## 触发自检

| 条件 | 执行 |
|---|---|
| 用户有要求 | 0.5 已执行；程度词已写入排序因子 |
| 模糊/候选>12 | 1.5 已执行 |
| 无忌口重选 | 2 标"未触发" |
| 健康限制 | 1 末转过滤 |
| 搭配类 | 双维缺口归属已标 |
| 多菜品 | 逐个添加，每步更新整体负荷 |
| 数值负荷 | 转写中已标注 |
| 辣度标注 | 体系已判定；菜单为准/数目排序，未绝对化、未跨菜单 |
| 支持度标注 | 每推荐项已标注；无支持项已查证或移除 |
| 参数非默认 | 6 中注明理由 |
| 底线例外 | 0.6 已声明理由 |
| 未覆盖 | 停，扩充，不臆造 |

## 铁律

1. 场景判定先于一切 2. 用户要求最高（含程度词） 3. 健康限制直接过滤
4. 底线默认激活 5. 稳定性先收敛候选 6. 禁名称标签 7. 数值负荷必标注
8. 多菜品逐个添加 9. 微示例仅抽象占位 10. 无候选如实说
11. 识图先判体系再逐项计数，不得凭记忆 12. 辣度以菜单自有体系为准，无图例仅按数目排相对序，不绝对化、不跨菜单
13. 推荐举例必标支持度；无支持项必查证，未查证不得输出
14. 任务动作须有指令原文依据，无依据不执行
