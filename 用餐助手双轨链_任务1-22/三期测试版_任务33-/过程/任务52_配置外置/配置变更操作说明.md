# 配置变更操作说明（任务52 · 配置外置）

> 本说明面向运维与后续任务执行人。
> 核心承诺：**今后更新模型或参考文件时，只改配置清单，不动任何脚本。**
> 唯一可配置源：`cloudfunctions/shared/assets.config.js`

---

## 〇、变更总原则

1. 所有可配置项集中在 `cloudfunctions/shared/assets.config.js` 一个文件。
2. 三种高频变更（换模型 / 加换速查表 / 换 prompt 卡）都**只改清单**，脚本（aiGateway / importRefTables / recommend）一行不动。
3. 清单**缺件时函数拒绝执行并列出缺项**，绝不猜默认值继续跑。看到报错 → 按报错点名去补清单或补文件。
4. 清单随各函数部署复制一份，**三处副本必须同版本**（见 §四）。

---

## 一、换模型（只改清单里对应 mode 的 model 字段一处）

**场景**：把某个功能位换用别的模型（例如把 `chat` 从 `deepseek/deepseek-flash` 换成别的）。

**操作步骤**：

1. 打开 `cloudfunctions/shared/assets.config.js`，找到 `MODEL_MAP`。
2. 只改对应 mode 那一行的 `model` 字段，一处即可：

```js
  chat: { channel: 'extend', model: 'deepseek/deepseek-flash' },
  //                      ↑ 只改这一个值
```

3. 保存 → 按 §四 把更新后的清单同步到三个函数目录 → 重新部署对应云函数。

**不要做的事**：不要改 `cloudfunctions/aiGateway/index.js` 等任何脚本；不要新增 mode（新增功能位属于开发任务，不在变更范围）。

---

## 二、加 / 换速查表（清单 EXPECTED_TABLES 加或改一行 + 传 md 文件）

**场景 A：新增一张速查表**（例如新表号 `102`）。

1. 把 md 文件传到云存储 `ref_tables/` 目录，文件名含表号数字段（如 `102新表标题.md`），或取精确文件名备第二步登记。
2. 清单 `EXPECTED_TABLES` 数组加一行：

```js
  { tableNo: '102', title: '新表标题', fileName: '102新表标题.md' },
```

   - 有精确文件名就登记 `fileName`（R 系列文件名不含表号的必须登记，如 051/062/058/068）。
   - 没有精确文件名就省略 `fileName`，导入器自动走数字段模糊兜底。
3. 如该表要进推荐默认装配，另行确认 recommend 侧"将查的表"清单（属开发变更，走任务书，不动脚本常量）。

**场景 B：换某张表的新版本文件**。

1. 新 md 传云存储 `ref_tables/`。
2. 清单里该 tableNo 那一行的 `fileName` 改成新文件名（走模糊兜底的表可不改清单，但建议登记精确名锁定）。

**不要做的事**：不要改 `cloudfunctions/importRefTables/index.js` 的匹配逻辑。

---

## 三、换 prompt 卡（清单改指向 + fileName，脚本不动）

**场景**：把某个角色换成新卡（例如详细卡 097 换新版本卡）。

1. 新卡 md 传云存储 `prompt_assets/`，文件名形如 `卡标题-AGT-xxxx.md`。
2. 清单 `EXPECTED_PROMPTS` 数组加新卡一行（promptId、title、fileName 逐字取自新卡 frontmatter）：

```js
  { promptId: 'AGT-xxxx', title: '新卡标题', fileName: '新卡标题-AGT-xxxx.md' },
```

3. 清单 `PROMPT_BINDINGS` 把对应角色的指向改到新 promptId：

```js
  CARD_DEEP: 'AGT-xxxx', // 详细卡（默认）
```

**只是换文件不换卡**（同卡 id 新文件）：只改 `EXPECTED_PROMPTS` 里该行的 `fileName` 即可，`PROMPT_BINDINGS` 不动。

**不要做的事**：不要改 `common/recommend.js`——卡 id 常量已从清单 `PROMPT_BINDINGS` 读取，脚本里没有卡 id 字面量。

---

## 四、部署注意（清单随各函数复制一份，三处副本必须同版本）

1. 云函数打包不含跨目录 require，`assets.config.js` 需**随各函数目录一并上传**：部署 aiGateway 时复制到 `cloudfunctions/aiGateway/` 可达路径（仓库内脚本统一 `require('../shared/assets.config.js')`，以仓库目录结构为准；实际打包按部署工具链保持一致）。
2. 三个函数（aiGateway / importRefTables / recommend 所在包）用的清单副本**必须同一次修改、同版本**：改清单后三处一起更新再部署，禁止只更新一处。
3. 清单自检不通过（缺 MODEL_MAP 位 / 表项数不足 / 卡项数不足 / 角色绑定缺失或指向不存在的卡）时，函数**拒绝执行并在报错里列出全部缺项**。看到报错按点名补清单或补云存储文件，不要改脚本绕过。
4. 改动清单前建议先跑一遍负向单测确认环境健全：`node tests/assets_config_negative_tests.js`（在任务52交付目录下）。
