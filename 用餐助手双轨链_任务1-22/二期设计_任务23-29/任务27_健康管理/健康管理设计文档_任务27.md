## 1. 竞品查证：四款现行健康管理软件的做法

### 1.1 薄荷健康

| 查证到的做法 | 对本设计的启示 |
|---|---|
| 食物库 50 万+ 条、覆盖 40 余种营养素数据 | 食物库是营养记录的底座，营养素粒度要到微量级 |
| 三餐记录后**自动生成营养摄入报表**：热量缺口/盈余 + 三大营养素占比 | "记录即反馈"：不需要用户主动查询，记录动作本身触发当日分析 |

| 拍照识别食物、绑定 HealthKit 同步设备数据 | 记录入口多样化（拍照/设备同步/手动），降低记录成本 |

| 查证到的做法 | 对本设计的启示 |
|---|---|
| 日记式饮食记录（Diary），按餐次（早餐/午餐/晚餐/加餐）组织 | 餐次是饮食记录的自然索引，所有周期分析都按餐次聚合 |

### 1.5 查证小结

**直接借鉴**：薄荷的记录即反馈、周/月筛选；MyFitnessPal 的日记餐次索引、双单位目标、食物贡献度下钻；Apple 的四类数据对象模型、幅度+持续时间趋势判定、多指标综合健康分、coaching 式建议；Keep 的能量缺口目标生成、运动纳入能量账、多目标支持。

## 2. 个人健康数据体系设计

### 2.1 数据模型（借鉴 HealthKit 四类对象）

| 数据类 | 字段 | 更新方式 | 更新频率 | 参考自 |
|---|---|---|---|---|
| **档案 characteristic** | 性别、出生日期、身高 | 用户录入 | 极低频（改一次记一次版本） | Apple HealthKit characteristic |
| **身体测量 sample** | 体重、体脂率、BMI、腰围 | 体脂秤同步 / 手动 | 日~周 | Apple 身体量度；薄荷档案 |
| **饮食记录 sample** | 餐次、食物、分量 → 各营养素摄入量 | 点餐助手自动写入 / 拍照识别 / 手动搜索 | 每餐（日频） | 薄荷三餐记录；MyFitnessPal 日记；Keep 饮食工具 |
| **运动消耗 sample** | 运动类型、时长、消耗热量 | 设备同步 / 手动 | 每次运动后 | Keep"运动+营养"闭环 |
| **体征 sample（可选）** | 步数、睡眠时长、静息心率 | 设备同步（HealthKit 等） | 日 | Apple 体征；薄荷 HealthKit 绑定 |
| **实验室数据 lab** | 空腹血糖、糖化血红蛋白 A1c、血脂（LDL/HDL/TG） | 用户录入体检报告 | 月~季 | Apple Longevity Tab 纳入 A1c/LDL |
| **目标 goals** | 体重目标、每日热量目标、三大营养素目标（比例+克双单位）、特殊诉求（控糖/增肌等） | 初始算法生成 + 月周期重校准 | 月级 | MyFitnessPal 自定义目标；Keep 能量缺口原理；薄荷个性化方案动态调整 |

**每条 sample 必带 `source` 字段**（设备同步 / 手动 / 拍照识别 / 点餐写入），与 Apple 的 source 对象一致——数据可信度争议时可追溯。营养数值一律由食物库计算供给，模型不估算。

### 2.2 数据流

```
记录（点餐/拍照/手动/设备）
    ↓ 写入
结构化健康数据存储（档案 + 时序 sample，带来源标记）
    ↓ 按周期聚合
周期分析引擎（规则引擎：统计 + 阈值判定，数字全部来自数据库）
    ↓
建议生成（规则引擎出结构化结论 → 模型只翻译成人话，禁止产出数字）
    ↓
日反馈卡 / 周报 / 月报
    ↓ 用户反馈（采纳/忽略）
回流分析引擎（下轮周期参考，学薄荷动态调整闭环）
```

## 3. 营养记录检测周期设计：日 / 周 / 月并行

三个周期不是三选一，是**三层架构**：日=决策层、周=行为层、月=战略层。下层喂数据给上层，上层回调重校准下层。

### 3.1 日周期 —— 决策层："今天该怎么吃"

- **触发**：每次记录即时反馈 + 每日晚间汇总一次
- **分析内容**：
  - 今日热量 vs 目标：缺口/盈余（能量缺口原理，参考 Keep）
  - 三大营养素达成率（每项：已摄入 / 目标）
  - 单餐结构均衡检查（蛋白质/碳水/脂肪比例是否失衡——参考 Keep 饮食工具，不止看全天总量）
  - **剩余预算 = target_k − consumed_k**（直接作为任务26点餐助手第2/3轮的输入：本餐还能吃什么、该补什么）
- **呈现**：一张当日反馈卡（数值+环形进度条），不长文
- **参考自**：薄荷"三餐记录后自动生成营养摄入报表"；MyFitnessPal Day View

### 3.2 周周期 —— 行为层："我的习惯怎么样"

- **触发**：每周固定一天生成周报（如每周日晚）
- **分析内容**：
  - 7 日均值 vs 目标（平滑单日噪声）
  - **达标天数**：每项营养素本周达标几天（"蛋白质 7 天达标 5 天"比"周均值 82%"更可行动）
  - 波动方差 / 周末效应（工作日 vs 周末摄入差——识别"周末崩盘"模式）
  - 营养素缺口排行（本周最缺的前 3 项）
  - 饮食结构模式：外食占比、跳过早餐次数、零食热量占比
  - **食物贡献度下钻**：哪些食物帮助/拖累目标（参考 MyFitnessPal food analysis）
- **呈现**：周报 = 高亮摘要 + 明细图表 + **1~3 条下周可执行调整建议**
- **参考自**：MyFitnessPal Week View / weekly digest；薄荷按周筛选；Apple 周视图

### 3.3 月周期 —— 战略层："方向和目标要不要改"

- **触发**：每月生成月度评估
- **分析内容**：
  - 月度均值 vs DRI（长期缺口/过剩定论）
  - 体重/体脂率变化趋势（结合身体测量数据）
  - **综合健康分**：多指标加权成一个可追踪分数（学 Apple Health Age：心脏/代谢/营养多类指标汇总；纳入 A1c/LDL 等实验室数据）
  - 目标进度校准：体重目标完成率、热量目标是否贴合实际（一直大缺口 → 目标定太高 → 重校准）
  - **方案重调建议**：是否调整每日热量目标、三大营养素比例、特殊诉求策略
- **呈现**：月报 = 综合健康分 + 趋势图 + 目标调整建议（coaching 式：给动作不给指责，参考 Apple）
- **参考自**：Apple Trends / Health Age / Longevity Tab；薄荷个性化方案动态调整；MyFitnessPal 跨周 digest

### 3.4 三层闭环关系

```
日周期（每餐决策）──记录累积──→ 周周期（习惯诊断）──累积──→ 月周期（战略重校准）
    ↑ target_k 每日来自目标库          ↑ 建议按周微调习惯            ↓ 重调目标
    └────────── 月周期回调改写 target_k、宏量比例 ──────────────────┘
                → 任务26点餐排序的营养分自动跟随新目标
```

## 4. 周期分析设计

### 4.1 趋势分析

- **滑动窗口平滑**：7 日 / 30 日移动平均，消除单日噪声（单日吃多不吃出趋势）
- **趋势判定双条件**（直接借鉴 Apple Trends）：**变化幅度 + 持续时间**
  - 判定公式：`|当前窗口均值 − 基准窗口均值| / 基准窗口均值 ≥ 阈值（如 5%）` 且 `持续天数 ≥ N（如 14 天）` → 才认定为趋势并提示
  - 单点偏离只进当日反馈，不升级为趋势告警
- **呈现**：折线图 + 趋势线 + 目标阈值带；数据点可下钻到具体记录（哪几顿饭造成的）

### 4.2 缺口分析

- **达标率**：`r_k = 实际摄入_k / DRI_k`（DRI 按参考文件：来自身体数据的目标体系，非模型生成）
- **缺口分级**（同一营养素，不同周期不同处置）：

| 级别 | 判定 | 处置 |
|---|---|---|
| 单日缺口 | 单日 r < 0.8 | 当日反馈卡提示，今晚/明天吃什么补（联动点餐助手） |
| 中期缺口 | 周均值 r < 0.8 且连续 2 周 | 周报列为重点，给食物替换建议 |
| 长期缺口 | 月均值 r < 0.7 | 月报定为结构性问题，调整方案/目标，或建议就医检查（如长期铁缺口） |

- **过剩对称分级**：钠、添加糖、饱和脂肪按同框架反向判定（r > 1.2）
- 缺口分析输出永远是**具体到食物的动作**（"你本周钙缺口 300mg/天，等价于每天少一杯酸奶"），不给抽象数字——数字来自统计，食物等价换算是规则库模板

### 4.3 建议生成

- **两级架构：规则引擎先行，模型后翻译**
  1. 规则引擎：周期统计 → 阈值/规则库匹配 → 产出结构化结论（缺口项、幅度、建议动作、关联食物候选）
  2. 模型只把结构化结论组织成自然语言表述，**禁止产出任何数字**（数字一律回引统计结果原文）
- **建议分级**：
  - 当日微调：具体、轻量（"晚餐加一份豆制品"）
  - 周计划：习惯替换（"这周把 3 次白粥换成牛奶+鸡蛋"）
  - 月方案：目标重校准（热量目标 ±10%、宏量比例调整、特殊诉求策略变更）
- **闭环回流**：每条建议带"已调整 / 忽略"反馈按钮；采纳率进入下轮分析上下文（学薄荷动态调整）；连续 3 次同类建议被忽略 → 降权不再推送（避免唠叨）
- **硬约束一致**：建议生成遵守全局硬约束——过敏原、素食标记只进规则不进打分（与任务26同一原则）；特殊医学诉求（如控糖）的建议模板需标注"非医疗建议，以医嘱为准"
