# 食知上线清单与安全审查清单

版本：v1.0 | 2026-09-18 | 编制：kimi | 依据：指南避坑清单+阶段4清单→食知实例化

## A. 上线清单（提审前逐项人工确认）

1. 类目=深度合成（AI问答/AI生成），与功能一致；主体=个体工商户已认证
2. 深度合成材料齐：微信云开发在用证明已提交
3. 隐私政策已发布且与实际收集项一致；分层授权弹窗逐项就位
4. 所有AI生成页面有"AI生成"标识；营养/健康建议页有非医疗声明
5. iOS端无任何虚拟支付痕迹（本版无付费功能，确认无残留文案即可）
6. 无诱导分享（识别/文案结果的分享按钮不得强制、不得利益诱导）
7. 测试账号、测试数据、调试日志输出全部清除
8. 包体积检查：主包无图片base64资源，图片全在云存储；分包加载就位
9. 审核备注写清：核心流程说明+测试路径（拍照识别可用示例图）
10. 提审前最后一眼由Walter本人看

## B. 安全审查清单（AI生成代码逐项过）

| 检查项 | 食知具体落点 |
|---|---|
| 用户输入校验转义 | 手动录入菜名/体重等所有输入框；防止注入云数据库查询 |
| 密钥管理 | 全局搜代码无sk-/AppSecret硬编码；模型Key只在extend.AI托管 |
| 数据库安全规则 | 五集合：未登录拒绝一切；登录用户只能读写自己的记录（按_openid隔离） |
| 越权 | 他人数据不可经改参数读取；导出接口只导本人 |
| 敏感数据 | 身体数据传输加密；日志不打印身体数据/照片地址 |
| 云函数权限 | 每个云函数最小权限；管理类函数不暴露给客户端 |
| 图片处理 | 上传图片类型/大小校验，防恶意文件 |
| 依赖 | 第三方依赖版本固定，无已知漏洞版本 |

## C. 上线后运营红线（指南：不委托AI）

- 发布决策、版本回滚、用户投诉处理=人
- 每周人工抽查AI输出质量（识别准确率、建议合理性）各10条
