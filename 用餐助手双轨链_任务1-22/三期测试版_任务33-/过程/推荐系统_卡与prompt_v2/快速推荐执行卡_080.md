# 快速推荐执行卡

## 适用

候选少、需求明、求快。动词：快速/直接推荐。允许以表现换速度。

**触发限定**：仅当进食者显式说明"快速"时使用本卡。

## 管线

| 步骤 | 动作 | 关键约束 |
|---|---|---|
| 0 | 场景判定 | 默认独立 |
| 0.5 | 用户要求过滤 | 最高标准。**程度词→排序因子** |
| 0.6 | 底线过滤 | **默认激活，查 R9（062）五维度** |
| 1 | 需求提取 | 仅取权重最高成分层条目。**全部要求写入** |
| 1.5 | 稳定性判定 | 触发：模糊指令。高者优先，同层级随机 |
| 2 | 前置过滤 | 忌口/重选 |
| 3 | 属性预筛选 | 摘要粗判。明显反向→降级。**数值负荷须保留**。**识图时先读图例/说明判定标注体系，再逐项对照符号计数；辣度以菜单自有体系为准，无图例按数目排序相对辣度，不绝对化、不跨菜单（查 051）** |
| 4 | 维度下推 | 高权重未命中→不匹配。**多菜品逐个添加** |
| 4.5 | 支持度标注 | **每个推荐项生成时同步标注：有来源 / 部分支持 / 无支持**。依据见"支持度标注规则" |
| 4.6 | 无支持项查证 | 标注"无支持"的项→查证其关键特性（口味强度/成分/禁忌/适用人群）是否符合各维度基本要求；查证通过→保留并附依据；未通过→移除并声明。**查证与初稿隔离作答** |
| 5a | 第一段输出 | **排名+分数+一句话理由**（约60 token），附"展开分析"选项 |
| 5b | 第二段输出 | 用户选择后展开完整分析（复用详细卡输出格式） |

## 支持度标注规则

| 标注 | 判定标准 | 处置 |
|---|---|---|
| 有来源 | 该项可直接由速查表（016/020/058/068/062）或菜单文本支撑 | 直接进入输出 |
| 部分支持 | 方向有表支撑，但具体特性（强度/禁忌）未在表中 | 保留，输出中标注"特性未查证" |
| 无支持 | 该项来自联想、常识或记忆，无任何表内依据 | 必须经步骤 4.6 查证，否则移除 |

**标注对象**：所有推荐举例（具体品种、具体品类特性声明）。类型级推荐（如"乳基饮"）若方向来自速查表，标"有来源"。

**已知局限（如实声明）**：标注依赖模型自评，自评不准时无支持项可能漏检（Lanham et al. 2023）。此为本机制的固有代价。

## 任务范围逐字引用（公共组件）

初始化块中每个计划动作标注其指令原文依据（逐字引用 1-3 词）；无原文依据的动作→停下声明"该动作无指令依据"，向发起人询问，不执行。

## 两段式输出规则

**第一段（默认立即输出）**：排名 | 候选 | 分数 | 一句话理由；附"展开完整分析"选项。
**第二段（用户选择后输出）**：完整需求提取与维度核对记录、转写过程、方向核对明细、支持度标注与查证记录、参数记录、局限声明。
**关键**：两段共用同一份后台分析，第一段是结果摘要，不是简化版分析。

## 按钮部署（占位）

**输入方式**：【占位：按钮界面】
- 第一屏：场景按钮（六选一）——【占位：天热解渴/吃辣了/解馋尝鲜/饿了顶饱/夜宵喝点/随便推荐】
- 第二屏：约束按钮（可多选/可跳过）——【占位：不吃辣/不要酒/清淡点/预算优先/跳过】

**输出方式**：【占位：卡片式排名界面】

## 铁律

1. 场景判定先于一切 2. 用户要求最高（含程度词） 3. 底线默认激活
4. 稳定性在模糊时触发 5. 前置过滤不受加速影响 6. 摘要不足不得降级
7. 数值负荷必保留 8. 多菜品逐个添加 9. 无候选如实说
10. 辣度识别同详细卡：菜单为准、无图例按数目排序、不跨菜单
11. 两段式不跳分析：第一段是完整分析的结果摘要
12. 推荐举例必标支持度；无支持项必查证，未查证不得输出
13. 任务动作须有指令原文依据，无依据不执行
