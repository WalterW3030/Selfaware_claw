# 任务类型检测指示（需求 → 加载文本映射）

> 用途：收到新指令时，先运行本检测，确定需要加载哪些规则文本。
> 加载顺序固定：通用规则（永远加载）→ 会话状态恢复（仅会话开始/重置后）→ 命中的任务类型规则。

## 检测方法

对指令文本逐条匹配以下关键词与意图，命中即加载对应规则文本。一条指令可命中多个类型，全部加载。

## 映射表

| 命中信号（关键词/意图） | 任务类型 | 加载文件 |
|------------------------|----------|---------|
| 任何指令 | 通用规则（必加载） | 加载文本_通用规则.md |
| 会话开始、重置后、新话题第一次行动 | 会话状态恢复 | 加载文本_会话状态恢复.md |
| 修改、优化、写、调整 + 脚本/代码/prompt/提示词/参数/关键词/阈值/预加载/preload/system prompt | 编写/修改脚本 | 加载文本_编写修改脚本.md |
| 测试、跑、运行、实验、N轮、N题、开始测试、重新测 | 运行实验 | 加载文本_运行实验.md |
| 汇报、结果、数据、指标、发给我、告诉我结论、核对、检查是否正确、列出结构 | 结果读取与汇报 | 加载文本_结果读取与汇报.md |
| 文件、保存、命名、版本、废弃、同步文件、记录到文件 | 文件与版本管理 | 加载文本_文件与版本管理.md |

## 检测流程

1. 把指令拆成待办条目（按通用规则的复述要求）
2. 每条待办对照映射表命中任务类型
3. 汇总去重，得到需加载的规则文本清单
4. 按固定顺序加载后，才开始执行

## 示例

指令："修改 modeC 的加载内容，然后跑 20 题测试，把结果发给我"
- 待办1 修改加载内容 → 编写/修改脚本
- 待办2 跑 20 题测试 → 运行实验
- 待办3 把结果发给我 → 结果读取与汇报
- 加载清单：通用规则 + 编写修改脚本 + 运行实验 + 结果读取与汇报

指令："把这些要求记录到文件"
- 待办1 记录到文件 → 文件与版本管理
- 加载清单：通用规则 + 文件与版本管理

## 兜底规则

- 拿不准命中哪个类型时，按"运行实验 + 结果读取与汇报"处理并说明理由
- 指令明确要求"先核对"时，无论命中什么类型，都追加加载"结果读取与汇报"中的核对响应部分
