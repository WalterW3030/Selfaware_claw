# 饮食推荐agent资料包评估：模型适配性与开发方案修改

版本：v1.0 | 2026-09-24 | 编制：kimi（Walter指定直接执行）
对象：主文件夹新上传7文件（commit c912059）——初始化prompt(029)/目的优先需求提取模型(003)/需求提取三条路径(002)/前置过滤与加速方案(004)/快速推荐执行卡(014)/详细推荐执行卡(023)/常见食品需求场景资料包(001)

## 一、模型能否处理：能，不需要升级模型

### 1. 长度评估（不是问题）

七文件合计13,695字符≈9-11K token。实际每次调用的装载量更小：初始化prompt(934字)+一张执行卡(766或1250字)+资料包相关类别节选(每类约800字)+用户输入+候选清单 ≈ **每次3-6K token输入**。deepseek-flash上下文1M、hy3也远超需求，长度方向无任何压力，输出侧每张卡的固定四段产出<1K token。

### 2. 能力评估（关键在指令遵循与语义推理，现有模型达标）

这套prompt系统对模型的真实要求逐项评估：

| 要求 | 难度 | deepseek-flash评估 |
|---|---|---|
| 每轮固定初始化块+固定输出四段（格式纪律） | 中 | ✅ 结构化输出是其强项（任务24-36全部JSON/模板产出零格式事故为实证） |
| 候选匹配禁关键词、做"方向核对"语义匹配 | 中高 | ✅ thinking low/medium档的语义推理足够；这是推理题不是检索题 |
| 双维分析（味型/成分分层陈述） | 中 | ✅ |
| 四参数取值必记录、部分匹配声明代价 | 中 | ✅ 属格式纪律 |
| 缺口声明/拒绝硬答（"速查表未覆盖就停下"） | 中 | ✅ 与既有is_food逃生门同类，模型守拒绝规则的表现已在识图模板验证 |
| 工具调用/视觉/长链规划 | 不需要 | — 纯文本单次调用 |

**结论：不需要升级模型。** 现有选型直接覆盖，且与既有双模式天然对齐：
- **快速推荐卡 ↔ recommend_fast = deepseek-flash 思考low**（快速模式同理低档求快）；
- **详细推荐卡 ↔ recommend_deep = deepseek-flash 思考medium，复杂个案可上探high**。
- 唯一注意：推荐是推理任务，**思考档位最低low，不能像识图那样off**——off档语义核对质量会掉。

### 3. 一个必须解决的缺口（不是模型问题，是资料缺口）

执行卡与初始化prompt引用了 **口味负荷速查表（016）、场景速查表（020）、机制原理册（017/026）**，这四个文件不在本次上传内。按agent自己的铁律"场景未被速查表覆盖→停下声明缺口，不得凭记忆编造"，**没有016/020表，agent会在大量正常输入下合法停摆**。需要Walter补传这两个速查表（机制原理册按规则只在用户质疑时查，可缓）。

## 二、开发脚本方案需要的修改（五处）

### M1 网关新增两个功能位（代码改动小）

MODEL_MAP 新增：`recommend_fast = deepseek-flash/thinking low`、`recommend_deep = deepseek-flash/thinking medium`。十位功能位。调参空间保留（详卡可上探high）。

### M2 搭配推荐的实现路线变更（设计层面最重要的修改）

任务26/32原定"规则引擎算双标准排序（口味cos+营养加权）+模型只做翻译"——现在Walter的资料显示推荐排序改由**提示词驱动的推荐agent**完成（方向核对+参数权重，模型自己做匹配判定）。分工重划：
- **规则层保留**：硬约束（过敏原/素食/忌口/重选）前置过滤（与执行卡步骤0/2一致）、数据供给（候选菜成分从营养库取）；
- **提示词层接管**：需求提取、双维转写、方向核对、加权汇总、输出四段——即执行卡全流程。
- 原S_taste/S_nutrition余弦排序方案降级为**备选兜底**（agent停摆时的降级路径）。需要对任务26设计文档出一份增补 reconciling（建议作为任务37派发）。

### M3 prompt资产管理机制（新增）

七个文件带AGT编号与supersedes链（如029 supersedes 028）——必须当**版本化资产**管理：入库存`prompts/recommend/`目录+云端配置集合存"当前生效版本号"，装配器每次调用按生效版本拼装（初始化prompt+执行卡+资料包相关类别+候选清单+用户输入）。禁止把prompt硬编码进页面代码。

### M4 候选"成分与效应摘要"预处理任务（新增一次性+增量）

前置过滤方案的属性预筛选要求每个候选菜有一份成分与效应摘要（首次整理此后复用）。新增脚本任务：批量读取营养库菜品→调网关生成摘要（hy3，便宜）→存新集合`dish_summary`；新菜入库时增量生成。这是T3数据层要加的一张表。

### M5 测试用例扩充（T9增补）

新增5条端到端用例：①初始化块格式校验（五字段齐全）②过敏原候选绝不进入推荐（规则层+agent双层验证）③速查表未覆盖场景→agent正确停摆声明缺口而非编造 ④参数记录四值齐全 ⑤快速/详细卡路由正确（快速模式不调详卡）。
