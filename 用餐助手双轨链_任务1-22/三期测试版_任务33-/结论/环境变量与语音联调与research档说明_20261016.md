## 一、SELFHOST_BASE_URL 与 SELFHOST_API_KEY

### 作用
aiGateway 云函数的**自备通道（selfhost）凭证**。网关有两条模型调用通道：

- **extend**：extend.AI 托管通道（cloudbase，`cloud.ai()`），默认且优先。
- **selfhost**：自备 OpenAI 兼容端点（如百炼/硅基流动），仅当两个环境变量都存在时才启用。

代码逻辑（`三期测试版_任务33-/过程/任务52_配置外置/cloudfunctions/aiGateway/index.js`）：
- L35 `selfhostReady()`：两个变量都在才返回 true。
- L83-87 `callSelfhost()`：`SELFHOST_BASE_URL` 去尾斜杠后拼 `/chat/completions`，`Authorization: Bearer ${SELFHOST_API_KEY}`。
- L78-81：未配置时返回 `selfhost_not_configured`，如实标注不静默。
- L91-99 `dispatch()`：指定 selfhost 但未配置 → **自动回退 extend**，并在结果里标 `_channelNote = 'selfhost_not_configured_fallback_to_extend'`（任务48 行为，调用方可区分通道）。

### 必要性
**当前非必需**。证据：
1. 网关部署与联调说明 §四（任务34 文档）：“默认关闭规则：两个变量任一缺失时，selfhost 通道判定为未就绪；即使某功能位 channel:'selfhost' 也会自动回退 extend（主线不阻塞）。不用 selfhost 时什么都不用配，默认全走 extend。”
2. 新机器环境配置指南 §五：只列这两个变量，无其他密钥。
3. 2026-10-16 实测：托管通道已通（chat 测试成功），未配 selfhost 不影响任何功能位。
4. 当前 MODEL_MAP 六位全部 `channel:'extend'`（`assets.config.js` ①节），没有任何功能位指向 selfhost。

结论：这是**备用/未来切换通道**的预备配置，不是当前运行必要条件。

### 配置方法（将来要配时）
1. 位置：微信开发者工具 → 云开发 → 云函数 → **aiGateway** → 配置 → 环境变量。
2. 两个变量：

| 变量名 | 值 | 说明 |
|---|---|---|
| `SELFHOST_BASE_URL` | 如 `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI 兼容端点根，**不含** `/chat/completions`（代码自行拼接） |
| `SELFHOST_API_KEY` | 你的自备 Key | 只填云控制台；不入库、不发群、不进代码 |

3. 添加第二个变量的操作（Walter 2026-10-16 16:59 答复）：填完第一组**先保存**，再点一次“添加”出第二行；找不到按钮截图确认界面版本。
4. 配后要切某功能位到 selfhost：改 `assets.config.js` 的 MODEL_MAP 对应行 `channel:'selfhost'` 并把 `model` 改成自备端点支持的模型名，重新部署 aiGateway（四处副本同步，见 assets.config.js 头注）。

### 纪律
密钥只进云控制台，不入库、不发群（指南 §五原文）。

## 二、TTS/ASR 语音联调

### 目标任务
让小程序支持**语音输入**与**语音播报**（任务42）：

- **ASR（语音→文字）**：个人主体小程序不支持微信同声传译插件，前端录音上传云存储后，由 **relayASR** 云函数转发**腾讯云一句话识别（SentenceRecognition）**返回文本。
- **TTS（文字→语音）**：**relayTTS** 云函数调**腾讯云 TTS**，三语播报（zh-Hans 普通话 / zh-Hant 粤语 / en 英语），语速 1.0。

### 代码现状（骨架已在库，未开通）
`过程/任务42_多语言与语音/cloudfunctions/relayASR/index.js`：
- 未配密钥 → 返回 `{ error: "asr_not_configured" }`，前端据此 toast“语音输入即将上线”。
- 已配 → 从云存储下载录音（前端传 fileID），TC3-HMAC-SHA256 签名调 `asr.tencentcloudapi.com`（ap-guangzhou）。
- 引擎白名单：`16k_zh / 16k_yue / 16k_en`（任务48 加白名单校验，缺参/不支持的值如实报错，不猜默认）。
- 所需环境变量：`TENCENT_ASR_SECRET_ID` / `TENCENT_ASR_SECRET_KEY`。

`过程/任务42_多语言与语音/cloudfunctions/relayTTS/index.js`：
- 未配密钥 → 返回 `{ error: "tts_not_configured" }`。
- 已配 → TC3 签名调 `tts.tencentcloudapi.com`（ap-guangzhou），返回 base64 音频。
- 音色映射（以腾讯云控制台开通为准）：zh-Hans=101001 普通话女声、zh-Hant=101019 粤语女声、en=301000 英语女声。
- 所需环境变量：`TENCENT_TTS_SECRET_ID` / `TENCENT_TTS_SECRET_KEY`。

### 联调方法（将来开通时）
1. **前提**：腾讯云控制台开通 ASR 与 TTS 服务，取两对密钥（SecretId/SecretKey）。
2. **配密钥**：云控制台 relayASR 环境变量加 `TENCENT_ASR_SECRET_ID`/`TENCENT_ASR_SECRET_KEY`；relayTTS 加 `TENCENT_TTS_SECRET_ID`/`TENCENT_TTS_SECRET_KEY`。两函数**无 npm 依赖**（只用 wx-server-sdk 内置 crypto/https），上传时选“云端安装依赖”即可。
3. **ASR 实测**：前端录音→传云存储→拿 fileID 调 relayASR，参数 `engine`（按界面语言映射 zh-Hans→16k_zh 等）+ `format`（与前端录音格式一致）+ `fileID`，预期返回 `{ text: "..." }`。
4. **TTS 实测**：调 relayTTS 传文本+界面语言，预期返回 base64 音频，前端播放验证三语音色。
5. **负向验证**：不配密钥时分别调两函数，预期 `asr_not_configured` / `tts_not_configured`，前端 toast 正常。
