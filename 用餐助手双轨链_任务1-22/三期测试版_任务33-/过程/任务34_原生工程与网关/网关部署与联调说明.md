# aiGateway 网关部署与联调说明

版本：v1.0 | 2026-09-18 | 适用：T2（2.2+2.3）产出 | 执行人：Walter

本文件覆盖两种部署路径、云函数本地调试步骤、一条测试 event 示例、常见问题报错对照。
所有操作在 Walter 本机完成；密钥只进云函数环境变量，绝不写进代码或发给他方。

---

## 一、部署前准备（一次性）

1. 微信开发者工具升级到 **Nightly** 版（稳定版对云函数 AI 能力支持可能滞后）。
2. 云开发环境已开通（H1），拿到**环境ID**。
3. `app.js` 的 `wx.cloud.init({ env: '<环境ID>' })` 已填（否则 callFunction 报 env 不存在）。
4. `project.config.json` 的 `appid` 已填正式 AppID（测试号不能用云能力）。
5. 云函数目录结构就位：
   ```
   cloudfunctions/aiGateway/
     index.js
     config.json
     package.json
   ```
6. （仅用 selfhost 时）准备好自备 API 的 Base URL 与 Key（如百炼/硅基流动的 OpenAI 兼容端点）。

---

## 二、部署路径 A：开发者工具右键上传部署（推荐，主线）

1. 微信开发者工具左侧文件树展开 `cloudfunctions/`。
2. 右键 `aiGateway` 文件夹 → **上传并部署：云端安装依赖（不上传 node_modules）**。
   - 选「云端安装依赖」：由云端按 package.json 拉 wx-server-sdk，避免本机 node_modules 差异。
3. 底部「云开发 → 云函数」等待部署完成，状态显示「已部署」。
4. （可选）在云函数详情页设置环境变量（见第四节）。

---

## 三、部署路径 B：CodeBuddy 对话部署（推荐，适合复杂改动）

1. 微信开发者工具安装 **CodeBuddy 扩展**（T2-H1，可选但推荐）。
2. 在 CodeBuddy 对话中说明：「部署 cloudfunctions/aiGateway 云函数到当前云开发环境」。
3. CodeBuddy 读取 `project.config.json` 的 cloudfunctionRoot 与 index.js，执行云端安装依赖部署。
4. 对比路径 A：CodeBuddy 适合边改边部署、复杂逻辑迭代；路径 A 适合快速单次部署。两条路径产出等价。

---

## 四、环境变量配置（仅 selfhost 通道需要）

位置：微信开发者工具 → 云开发 → 云函数 → aiGateway → **配置 → 环境变量**。

| 变量名 | 值 | 说明 |
|---|---|---|
| `SELFHOST_BASE_URL` | 如 `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI 兼容端点根，**不含** `/chat/completions` |
| `SELFHOST_API_KEY` | 你的自备 Key | 只填此处；不要发任何人、不要进代码 |

**默认关闭规则**：两个变量任一缺失时，selfhost 通道判定为未就绪；即使某功能位 `channel:'selfhost'`，也会自动回退 `extend` 通道（主线不阻塞）。不用 selfhost 时**什么都不用配**，默认全走 extend。

> 切某功能位到 selfhost：改 `index.js` 的 MODEL_MAP 对应行 `channel:'selfhost'` 并把 `model` 改成自备端点支持的模型名，重新部署。

## 五、本地调试步骤

1. 云开发 → 云函数 → aiGateway → 右侧「**本地调试**」（或「云端测试」）。
2. 若用本地调试：选「本地调试」运行环境，确认已安装依赖（云端安装依赖则用「云端测试」）。
3. 在测试面板填入测试 event（第六节），点「运行」。
4. 查看返回：应返回模型文本；若是 `numeric_leak_blocked` 说明红线触发（nutrition 模式且模型吐了数字，属预期拦截）。
5. 看日志：云函数日志可见上游错误详情（如模型未开通、思考档位不识别）。

## 六、测试 event 示例（mode=chat）

```json
{
  "mode": "chat",
  "messages": [
    { "role": "user", "content": "用一句话介绍膳食纤维的作用" }
  ]
}
```

**预期**：返回 `chat` 功能位模型（deepseek-flash，思考 low）的文本响应，无 error 字段。

**核对要点**：
- 返回无 `unknown_mode` → MODEL_MAP 键正确。
- 返回无 `upstream_error` → extend 通道与模型开通正常。
- 若返回结构含 `choices[0].message.content` 或 `text`，`extractText` 均可解析。

**识图位补充示例**（验证图片进 messages，需多模态模型已就绪）：
```json
{
  "mode": "recognize",
  "messages": [
    { "role": "user", "content": [
      { "type": "text", "text": "识别这张图里的食物，返回 is_food 与候选名" },
      { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,<base64>" } }
    ]}
  ]
}
```

## 七、常见问题报错对照

| 现象 / 报错 | 可能原因 | 处理 |
|---|---|---|
| `env 不存在` / `-501000` | 环境ID未配或填错 | 检查 `app.js` 的 `wx.cloud.init({env})`，与云开发控制台环境ID逐字比对 |
| 基础库过低 / `cloud.ai is not a function` | 基础库 <3.15.1 或 wx-server-sdk <4.0.1 | 基础库调到 ≥3.15.1；确认 package.json `wx-server-sdk ~4.0.1` 且用「云端安装依赖」部署 |
| `模型未开通` / 上游拒绝 | 该模型在云开发控制台未开通（如 deepseek-flash 多模态未上架） | 去云开发控制台「AI → 模型」核查在售列表（T2-H2/P7）；识图位若 deepseek-flash 无图则切备选 qwen3-vl-flash |
| `unknown_mode` | 传了 MODEL_MAP 外的 mode | 只用六功能位名；检查前端 data.mode |
| `upstream_error` | 上游调用失败（网络/参数/额度） | 看云函数日志 detail 字段；确认成长计划额度或用量 |
| `numeric_leak_blocked` | nutrition 模式模型自产了数字 | **预期拦截**，非故障；数值应由数据库填充后模型只翻译 |
| `selfhost_not_configured` | 某功能位切了 selfhost 但环境变量没配 | 配 `SELFHOST_BASE_URL`/`SELFHOST_API_KEY`，或改回 extend |
| 本地调试 `fetch is not defined` | 云函数运行时未提供全局 fetch | 改用内置 https 模块或部署后用「云端测试」验证（见文末待核对项） |
| callFunction 超时 | order_deep / 识图耗时长 | config.json timeout 已设 60s；仍超时排查上游模型延迟 |
